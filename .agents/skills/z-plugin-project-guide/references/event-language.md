## Contract

- Normal Profiler captures include `ZCode.Program [uid] name` for each interpreter slice and nested child, plus `ZCode.Cmd name` for command starts. Match inclusive time versus Self before blaming VM dispatch for command/subprogram work. Program labels are cached by the runtime metadata and shared immutably through snapshots; command labels are cached across GetNew instances. Keep scopes balanced across returns/errors/cancellation and avoid per-instruction markers or per-call formatted labels. This instrumentation is gated by ENABLE_PROFILER and does not alter the runtime budget or retain asynchronous arguments.

- Interpret deep-profile totals include per-method instrumentation across thousands of stack/property/Box operations; establish actual frame cost with Deep Profile disabled before assigning a bottleneck to the VM. `CodeInterpreterRuntimeRegression -InterpreterBenchmark` runs warmed Stopwatch medians with recording disabled for Story 1 program 26 (111 real hostility calls across 37 owners) and 40-owner synthetic batches using real compiler/interpreter output (scalar loops, nested programs, mutable dictionary copy-in/out and commands). It includes root Reset work, runs no game scene or saves, and is a synthetic throughput comparison rather than the current Story's frame time. Keep published bytecode revision, cancellation, ownership and timeout checks intact when optimizing.

- Completed custom-program calls return their private `SubProgramContext` to a main-thread free list shared by interpreters (maximum 128 retained frames). Reuse the Data, Interpreter, stack, heap and heapTemp containers only after argument copy-out and return transfer. Clear containers and program/root/cache references, never the referenced Boxes: returned dictionaries and caller parameters may still own them. Nested slices pass their completion and return value by value. An exclusive scalar result can transfer from the child stack to its caller for later recycling. Public RetInfo, its errors and values retained by commands keep independent lifetimes. Pending/recursive calls keep separate live frames and their captured program revisions. Cancelled, errored or currently executing contexts are retired rather than reused, preserving cancellation identity for retained callbacks; Reset/Cancel release descendant calls safely. Oversized containers are not retained. This does not pool registered root EventInterpretData records or change instruction/depth/time budgets. Cache immutable `param1`, `param2`, ... names for both copy-in and copy-out, with the cache/free list reset at subsystem registration.
- `CmdBase.Execute` resolves variable arguments and source order without allocating empty dictionaries for scalars. A command that needs writable/member storage must call `GetOrCreateDictionary()` at that use site. Read-only dictionary enumeration accepts null as empty (GetKeys/GetValues and choice lists); Len retains zero for null. Vector commands explicitly request their component dictionary and preserve existing missing-member errors. Stateless, synchronous single-result readers may implement SynchronousQueryCmd. Query borrows a read-only span of inputs for the duration of the call and must return an independent Box tree. With all arguments supplied, the VM reuses a cleared per-interpreter argument buffer and consumes the result directly. Ordinary and asynchronous commands retain independently owned arguments. Do not restore unconditional dictionary creation in the generic command boundary.

- `GameEventUnitSubscriptions`, owned by each GameEventController, selectively subscribes live MapUnits to categorized event channels. Registration resolves prototype plus local event keys when a Unit is added; existing Units are indexed once on first dispatch/restart. EverySecond visits only subscribed Item/Character/Object owners, in those groups; Tiles retain global-variable subscriptions from main-texture slot 0. Global changes collect only Any and the changed UID channels, deduplicate owners, then queue each owner's Any before exact handlers with independent program heaps. Do not scan all MapUnits or construct per-Unit arguments on steady-state notifications. Unit removal and controller Reset/ClearScene unregister owned channels; Data identity and scene guards reject stale owners. Unit extra/main-texture changes refresh those owners, while registered Product/texture event replacement and EventModify invalidate inherited subscriptions. Generated SetActions precede field assignment: retain pending markers across notifications nested inside setters until the announced value is installed. Missing Product registration triggers a rebuild only when a Unit awaited that source; unrelated new Products do not rebuild the whole map. In-place event dictionary/list edits must emit EventModifyEvent through the existing editor mutation APIs. No serialized subscription cache is added.

- `onDestroyEvent` is the pre-removal trigger for `Destroy` and its legacy aliases on Character/Object/Item scene Units. Resolve prototype events before the local suffix, pass the exact `$so$u:UnitUid$so$` owner as `param1`, and run the existing event scheduler until every queued handler finishes before removing the snapshotted targets. No-handler calls remain synchronous. Per-controller Data-identity reservations make repeated/self/cyclic destruction no-ops while the original operation is pending. Handler events may run under their calling event's Pause via a runtime-only blocking-parent chain; unrelated events remain blocked. Pending removals and child hooks share the caller task's cancellation/reset/scene lifetime, and UID reuse cannot retarget either. Direct Map removal/editor deletion does not invoke this command-specific trigger. Keep event snapshots, normal instruction budgets and independent handler heaps; never pump the interpreter or LateUpdate recursively to finish hooks.

- `FadeIn(seconds)` and `FadeOut(seconds)` (GameCmd UIDs `100119`/`100120`, Effect CmdLab `10013`) accept one numeric duration and return immediately, allowing the next statement in the same interpreter pass. Omitted/legacy empty arguments retain the one-second default. They show the shared `UiPlayEffectCtrl`; its black `img_` animates alpha 0→1 or 1→0 for the requested unscaled seconds, then both close the overlay. Nonpositive/nonfinite durations complete immediately. Each Show resets the graphic and waits for its first active Canvas submission before starting the clock, so loading before first render cannot consume an independent FadeOut's black starting frame. The one-shot Canvas callback only updates timing state; Hide/completion/restart unsubscribes it. A newer call replaces/restarts the active fade rather than queuing or waiting. Do not retain an interpreter task, add an implicit Wait, or hold a fully black FadeIn overlay after completion.

- Statements include assignment, calls, if/else, for, while, break, continue, and Return.
- Keywords are case-sensitive: the return statement is `Return`, not lowercase `return`. Keep this existing grammar. For `return 1;`, the parser reads a variable expression named `return` and reports the missing statement semicolon at the following number; multiple such statements yield independent diagnostics. Capitalizing `Return` fixes that source without changing `&&` or nested if/else syntax.
- In the syntax tree, an `if` is the only Reserved node for the condition; its branch bodies are Action nodes named `then` and `else`. Event-editor entry rows rely on those distinct names and must not treat a branch container as another conditional.
- Any for clause may be empty.
- Operators include arithmetic with modulo, comparisons, unary not (`!`), short-circuit or (`||`), and short-circuit and (`&&`).
- For `+`, `-`, `*`, and `/`, a nonempty dictionary with a scalar applies the operation to each field in operand order (including scalar/dictionary). Two dictionaries operate on matching keys only. Arithmetic returns a new dictionary without mutating either input; scalar arithmetic and division-by-zero behavior remain unchanged.
- Event-editor Operator rendering has an arity-aware, recursive fallback independent of the command-description table. Missing descriptions must not reduce a compound condition to a lone operator token. Keep both binary operands in source order (`subNodes[1]`, then `subNodes[0]`), unary/postfix order, nested grouping, and editable child identities; do not change compiled/stored programs as a display fix.
- Decompilation renders expressions according to the recursive-descent parser's precedence and associativity, rather than parenthesizing every binary node. Keep parentheses for lower-precedence children and equal-precedence right children of left-associative operators (including arithmetic, whose reassociation can alter results); assignments are right-associative. Separate binary/unary `+` tokens so `a+ +b` cannot become postfix `++`, and retain grouping before numeric member access where the lexer would consume the dot as part of a number.
- Decompilation uses LF line endings and indents each statement inside an `if`/`else`, `while`, or `for` brace block by four additional spaces per nesting level. Opening and closing braces stay aligned with their controlling statement. It places spaces around binary operators, after argument commas, and after nonempty `for`-clause semicolons, while keeping function calls, member/index access, postfix increment, unary operators, strings, and explicit empty argument positions intact; formatting must preserve compile/decompile round trips.
- Postfix `++` and `+=` are supported as standalone statements and `for` initialization/iteration clauses for variables or one-layer member/index targets. They update the target once and do not produce an expression value; other expression contexts are rejected. `Return i++;` follows statement order (`Return i; i++;`), so it returns the old value without running the unreachable increment.
- Strings accept single or double quotes plus common and unicode escapes.
- Generate LF-only source with spaces; use GamePause and GameContinue in new code.
- Prefer Compiler.TryCompile and ProgramDataForm.Data.TryApplyCode. Never persist partial output after errors.
- After successful syntax parsing, the compiler validates every call against `BaseData.cmdDic` (including registered aliases) and `ProgramDataForm.DataByName`, using the same case-sensitive lookup as the interpreter. Missing methods produce `方法检查` diagnostics naming the identifier and its source location, with no executable output. Nested and unreachable calls are checked too; strings and member names are not calls. Skip this phase when syntax errors already exist so recovery does not add misleading diagnostics. Register all custom programs before compiling a batch, as `LoadEvent` does, to allow forward and recursive references. `TryApplyCode` keeps the last valid program untouched on a missing-method error.
- Function arguments bind in source order; expression statements must leave the stack balanced.
- `ShowTeamerSelect()` (GameCmd UID `100104`, zero arguments, void) only opens the original party-management window and waits for it to close; its row selections remain deployment/replacement UI state, not an event return. `SelectOneTeamer()` (UID `100135`, UI CmdLab `10022`, no arguments, one `character` return; default `teamer = SelectOneTeamer();`) independently opens the generic Notify Choose dialog with all valid `Progress.team` Products, including deployed/dead members, in ascending UID order with duplicates removed. Do not modify membership, deployment or the current Character. Entry keys are UIDs, so repeated display names stay separate. Return the chosen exact `$ch$UID$ch$` or empty for no valid team/Progress, external dismissal, a removed/memberless/replaced Product or changed Progress. Require a choice while the dialog exists; event cancellation removes only that operation's ChooseInfo. Late callbacks cannot resume canceled/finished work or close another choice. `Run-TeamerSelectRegression.ps1` exercises actual command/UI sources against lightweight service/UI spies; `CharacterPartyRegression` additionally verifies native metadata/default compilation, serialization and empty-team interpretation.
- `Len(value)` returns the consecutive numeric-key prefix starting at `"0"`, not the total dictionary count: sparse/named/noncanonical keys must retain their existing first-gap behavior. Dense-list detection parses distinct canonical decimal keys within `[0,Count)` without constructing `i.ToString()` for every probe; sparse lists use reusable main-thread bit scratch space, never a cached length keyed only by dictionary identity/Count. Same-count edits must be reflected on the next call. No blanket compiler hoisting of Len in loop conditions is safe because a body may change the list. List loops must use `i < Len(list)`: member reads retain their existing auto-create-zero semantics, so `i <= Len(list)` followed by `list[i]` grows the list together with the loop counter and can continue indefinitely across instruction-budget yields. Temporary Len/missing-index investigation logs have been removed; keep normal source-mapped runtime errors. `LenCommandRegression` covers legacy equivalence, mutable dictionaries, large-list loop execution and allocation-counter calibration; .NET-host measurements do not establish identical Mono/Player byte counts.
- Cmd calls may omit trailing arguments, and explicit empty slots such as `Cmd(,value,)` are preserved. Each omitted Cmd argument reaches `ExecuteInternal` as an empty-string Box; excess arguments remain an error. Custom stored-program calls keep exact parameter-count validation.
- `ShowDialog` has ten canonical parameters: background, avatar, title, content, optional audio, and five optional illustrations from left to right. Four- and five-argument calls remain valid because omitted trailing parameters are padded; stored event files do not need migration.
- `ShowText(text,scale,showTime)` (GameCmd UID `100134`, UI CmdLab `10022`) mirrors `ShowImage` except its first argument is an authored string. Return the same `uiImg`/`$ui$UID$ui$` handle and reuse `SetImagePosition`, `SetImageRotate`, `SetImageOpacity` and `DeleteImage`; do not add a parallel text handle registry or control-command family. `scale` multiplies the PlayAsset `txt_` prefab's original font size; preserve literal text/line breaks without localization. Images and text share `ImageUiItemForm` records, timers, rendering rows and existing persistence, with mutually exclusive graphics per record. The duration uses the shared bounded scaled UI clock, not an extra interpreter wait.

- Event-editor Cmd parameter replacement compiles one expression as a temporary terminated statement. Add the missing trailing semicolon only in that single-node editor path; complete stored event programs continue to require explicit statement terminators.
- Event-editor Item creation/insertion compiles the chosen command's table `defaultCode` as a complete statement. Keep this contract in the table rather than adding a generic terminator in Item UI. Do not relax the full stored-program compiler's semicolon requirement.
- Recompile each complete ef record from source after code-generation changes. Keep zCode and zCodeMap counts equal. A migrated ef record may temporarily store both caches as empty; `GameSaveController.LoadEvent` recompiles it from source after registering all programs, and the next save persists the rebuilt caches.
- Scene and story trigger arguments use `param1`, `param2`, and `param3` in place of the retired `self`, `target`, and `delta` names. `param1` is the emitting unit/product, `param2` is the touched target, used item, skill, or changed parameter name (depending on trigger), and `param3` is the character-parameter change amount. Program-to-program calls must pass needed values explicitly; subprograms do not inherit the trigger heap. Loading an older ef recompiles standalone legacy identifiers from source while leaving string literals unchanged.
- Clicking a Play interaction option (`onInteractEvent`) passes the interacted Character as `$ch$ProductUid$ch$` in `param1`, not its scene Unit UID. - `onTileTouchEvent` is a unit-owned scene trigger fired when a moving MapUnit enters a Tile physical Collider. Its heap exposes the moving unit as `param1` and the Tile as `param2`, both using the existing scene-object handle format; map-edge contact remains `onBoundaryTouchEvent`.
- Deferred MapUnit lifecycle callbacks such as `onShowEvent` and `onBoundaryTouchEvent` must verify that the original unit data is still registered in `UnitForm` by both UID and reference identity before dispatch. UID equality alone is insufficient because removed unit IDs can be reused.
- Removing an ObjectUnit, CharacterUnit or ItemUnit immediately marks its other active scene-trigger interpreters and their polled asynchronous tasks as cancelled, and releases their `OnceDuring` and blocking state. The interpreter currently performing the removal may finish only its current `Interpret` pass; after it returns to the event scheduler, it and its tasks are cancelled before another pass or task poll. New and resumed events validate the original `UnitForm.Data` reference as well as the UID so UID reuse cannot revive stale work.
- Every polled task started by an event is owned by that root `EventInterpretData`, including tasks started inside subprograms. Normal completion, cancellation, and scene/controller clearing must cancel all owned tasks before removing the event, so no task may outlive its event.
- A pending Cmd captures its call PC/name, argument count, declared return count and discard mode once. Waiting/completion polls must not recreate the command, allocate another argument array, resolve arguments again or re-read changed command metadata/registries. Validate results and balance the stack using the captured counts. Reset permits a new invocation; cancellation remains event-owned. A suspended custom program likewise resumes its captured program/signature rather than re-resolving a changed/removed registry entry or a newly registered same-name Cmd.
- Published compiled `zCode` and `zCodeMap` lists are immutable, including raw-bytecode fixtures and runtime snapshots. Build a new list before publishing any change; never change elements, counts or ordering in place. `TryApplyCode` and repeated Compiler use already produce replacement lists. `ProgramDataForm.Data.CreateRuntimeSnapshot()` preserves the concrete metadata type and captures private code/source-map lists once per authored revision. At new event/subprogram startup, only reference identity determines whether either source list changed; no content scan or in-place edit support is needed. Unchanged executions share the private lists, not their metadata wrapper, PC, stack, heap or task. Active snapshots continue their old revision after replacement. Current EventProgram derived metadata adds only scalar `labId`; explicitly snapshot any future mutable derived fields. Parsed opcode/numeric/integer arrays are weakly cached by immutable compiled-list identity, without token-change checks; Reset releases local views without invalidating other interpreters. Do not key caches by recyclable program UID or persist them into Forms/saves.
- RetInfo's public default construction still supplies an independent empty Box and error list; internal construction with a supplied return value must not first allocate and discard another default Box. Arithmetic already creates independent scalar/dictionary results, so `+=` stores its new result without another deep copy; ordinary assignment and subprogram argument copy-in/copy-out semantics stay unchanged.
- Scalar/string/reference factories leave `Box.dic` null (an empty dictionary); `DeepCopy` preserves this lazy state. `CreateBox` remains the writable-container factory. Use `GetOrCreateDictionary` when accessing/writing members. `GetBox` does not initialize dictionaries for scalar reads; Dictionary writers materialize storage at their write site. DeepCopy preserves both null and allocated empty dictionaries, and checks the active copy path for Boxes with children.
- `GetGlobalVar(name)` and `SetGlobalVar(name,value)` are executable basic CmdLab commands (GameCmd UIDs `100121`/`100122`). Globals are named, case-sensitive `EventGlobalVariableForm` records holding a full Box tree, shared by events/subprograms across scenes within one Story. Both reads and writes deep-copy values; editing a fetched local value does not write back without Set. Missing/null-valued globals and empty/non-string names read as numeric `0`; empty/non-string names do not write, and reads do not create records. Do not put globals in interpreter heaps or reset them during scene/event-controller clearing. Story save/load/reset owns their lifetime through `egvf`.
- Global-variable change bindings use existing Scene/Product/MapTexture `events` and Unit `extra.events` dictionaries as `onGlobalVarChangeEvent$<GlobalVariableUid>`; the empty suffix matches Any. Keep the variable UID stable across renames. `SetGlobalVar` commits its owned value before publishing `GlobalVariableChangedEvent`; publish only when the effective Box value changes (missing/null = numeric zero, numeric versus string types are distinct, nonempty dictionaries compare keys/values recursively independent of key order and Box UID/reference metadata). Unit bindings resolve inherited events before local additions, retain the Unit UID and Data identity as execution owner, and cancel on owner removal or scene exit. Tiles inherit the events of their main texture (slot 0). Scene-panel and Unit bindings share one argument layout: `param2 = variable name`, `param3 = numeric new value minus old value`, matching Character parameter-change name/delta semantics. Missing/null is numeric zero; changes involving text or a nonempty dictionary still trigger but receive numeric delta zero. `param1` is zero for Scene bindings and the exact owning scene Unit (`$so$u:UnitUid$so$`) for Unit bindings, so position/mutation/destruction commands target that instance. Preserve the existing full new-value snapshot in `param4` for both scopes; scripts can also read the committed value with `GetGlobalVar(param2)`. Each handler program receives independent deep snapshots through `TriggerEventExecute(copyDefaultHeap: true)`; existing callers retain their original heap semantics. Same-value assignments cannot create a self-trigger loop. Deleting an authored global removes its specific bindings across Scenes, Products, MapTextures, live Units and unloaded authored map extras before its UID can be reused; Any bindings and reusable Event Programs remain. No new Scene schema or old-save migration is required.
- All Interpreters share one main-thread pool of private temporary scalar/reference Boxes, capped at 128 free entries globally. Only free Boxes are shared; current ownership and deferred-consumption lists remain per Interpreter. Return clears owner/value/dictionary references so the static pool cannot retain an Interpreter or its scene/heap; rent assigns the new owner. SubsystemRegistration clears the free pool for a new Play lifetime, including when domain reload is disabled; individual Reset/Cancel do not clear other Interpreters' free entries. Pop/Pop2/PopMany defer recycling until the instruction's finally block, after all operands are consumed; instructions with no consumed Boxes skip the recycler call. Wait's repushed countdown and budget-suspended stack values stay live. Heap/dictionary results are independent nonpooled Boxes; scalar arithmetic used for `+=` and dictionary fields creates owned results directly. Export to a command or RetInfo permanently detaches a temporary from its pool before exposing it, so synchronous/asynchronous command captures and retained returns cannot be overwritten by later instructions or executions. Reset/Cancel detach outstanding stack temporaries without mutating their contents. Never recycle arbitrary heap, dictionary, command or return Boxes, clear a shared copy-out dictionary, or share a live literal across interpreters.
- The pool initializes/clears its private unregistered TemporaryBoxes through `BoxDataForm.Data.InitializeTemporaryValue/ClearTemporaryValue` in the hand-written partial, accessing backing fields directly. These internal methods must never be used on ordinary/registered/escaped Boxes; their generated setters, indexes and notifications remain authoritative. `Pop2` validates both inputs once, reports null/underflow before removal, removes the tail in one batch and updates top once. Intrinsic results use `PushResult` after that validated pop, while ordinary pushes at startup/call boundaries retain validation. Arithmetic resolves root operands once at entry and dictionary children once per recursion; already-resolved scalar/broadcast operands are not passed through GetBox again. Preserve operand order, string formatting, fresh dictionary results and division/modulo-by-zero diagnostics.
- Event scheduling reuses a frame-start snapshot ordered by each event's runtime-only monotonic enqueue sequence, independent of recycled UIDs/Dictionary slots, and ignores reentrant LateUpdate calls; events created during the current pass execute on the next pass. Tasks are indexed by root event and scene-owner Data **reference identity**, and indexed cancellation must not affect reused UIDs. Stable task compaction preserves task callback order and the existing same-pass polling of appended tasks. Scene/reset lifecycle changes invalidate the old compaction pass so callbacks cannot reinsert old work or discard replacement work. Exception cleanup preserves unpolled tasks and releases the reentrancy guard. Keep the current-removing-event pass exception and root ownership of subprogram tasks.
- `Pause`/`GamePause` gates both event bodies and every `GameEventController` task callback, including `StartTask`'s immediate poll. ## Limits and validation

Story 1's authored projectile attacks store numeric `所属Team = GetCharacterParameter(param1,"Team")` and `伤害 = GetCharacterParameter(param1,"攻击")` on every generated Object, rather than retaining `所属人物`. Homing compares candidate Team against the projectile's stored Team; Character hits subtract target defense from stored damage and clamp at zero, while destructible scenery subtracts the same stored damage. Same-Team Character contact (including the firing Character) is a complete no-op: no damage, stun, hit effect/audio or projectile destruction. Keep the existing 0/1 enemy and Team-2 neutral damage rules and each source event's optional stun. Do not read the firing Character during projectile behavior, so removal or subsequent attack/Team changes cannot alter an in-flight shot. `.agents/skills/z-plugin-project-guide/scripts/migrate-projectile-damage.py` performs the explicit offline `ef` migration with preview, hash guards and byte-for-byte backups; only changed source/compiled-cache fields are rewritten. `LoadEvent` rebuilds their cleared `zCode`/`zCodeMap` after all programs register. Run `StoryProjectileDamageRegression` against both repository and local Story copies before applying to persistent data; reload the Story afterward so in-memory UGC state cannot overwrite the migrated file.

The runtime budget is 4096 instructions per top-level call, child depth is 64, and source/AST depth is 256. Each root Interpreter additionally enforces `MaxExecutionSecondsPerFrame = 1` using monotonic Stopwatch ticks, shared with synchronous subprograms and accumulated over repeated slices within the same Unity frame. Count only active interpretation, not time between polls, other events or previous frames; Reset clears the counter. Check instruction and completion/yield boundaries so a slow final or async-start Cmd also fails. Timeouts return a complete RetInfo with the existing source-mapped InterpretError (program, PC/opcode, line/column, source and elapsed time), then the existing GameEvent scheduler shows its runtime-error Popup, cancels owned tasks, removes the event and releases Pause/OnceDuring state. This is cooperative at instruction boundaries: a synchronous C# Cmd cannot be interrupted until it returns. Instruction-budget exhaustion remains a non-error yield. `InterpreterTimeoutRegression` tests real-clock timeout, nested/cumulative/frame semantics and the scheduler's notification/cleanup path.
