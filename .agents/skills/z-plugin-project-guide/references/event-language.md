## Contract

- Statements include assignment, calls, if/else, for, while, break, continue, and Return.
- Keywords are case-sensitive: the return statement is `Return`, not lowercase `return`. Keep this existing grammar. For `return 1;`, the parser reads a variable expression named `return` and reports the missing statement semicolon at the following number; multiple such statements yield independent diagnostics. Capitalizing `Return` fixes that source without changing `&&` or nested if/else syntax.
- In the syntax tree, an `if` is the only Reserved node for the condition; its branch bodies are Action nodes named `then` and `else`. Event-editor entry rows rely on those distinct names and must not treat a branch container as another conditional.
- Any for clause may be empty.
- Operators include arithmetic with modulo, comparisons, unary not (`!`), short-circuit or (`||`), and short-circuit and (`&&`).
- For `+`, `-`, `*`, and `/`, a nonempty dictionary with a scalar applies the operation to each field in operand order (including scalar/dictionary). Two dictionaries operate on matching keys only. Arithmetic returns a new dictionary without mutating either input; scalar arithmetic and division-by-zero behavior remain unchanged.
- Event-editor Operator rendering has an arity-aware, recursive fallback independent of the command-description table. Missing descriptions must not reduce a compound condition to a lone operator token. Keep both binary operands in source order (`subNodes[1]`, then `subNodes[0]`), unary/postfix order, nested grouping, and editable child identities; do not change compiled/stored programs as a display fix.
- Decompilation renders expressions according to the recursive-descent parser's precedence and associativity, rather than parenthesizing every binary node. Keep parentheses for lower-precedence children and equal-precedence right children of left-associative operators (including arithmetic, whose reassociation can alter results); assignments are right-associative. Separate binary/unary `+` tokens so `a+ +b` cannot become postfix `++`, and retain grouping before numeric member access where the lexer would consume the dot as part of a number.
- Decompilation uses LF line endings and indents each statement inside an `if`/`else`, `while`, or `for` brace block by four additional spaces per nesting level. Opening and closing braces stay aligned with their controlling statement. It places spaces around binary operators, after argument commas, and after nonempty `for`-clause semicolons, while keeping function calls, member/index access, postfix increment, unary operators, strings, and explicit empty argument positions intact; formatting must preserve compile/decompile round trips.
- Postfix `++` and `+=` are supported as standalone statements and `for` initialization/iteration clauses for variables or one-layer member/index targets. They update the target once and do not produce an expression value; other expression contexts are rejected. `Return i++;` follows statement order (`Return i; i++;`), so it returns the old value without running the unreachable increment.
- Strings accept single or double quotes plus common and unicode escapes.
- Generate LF-only source with spaces; use GamePause and GameContinue in new code.
- Prefer Compiler.TryCompile and ProgramDataForm.Data.TryApplyCode. Never persist partial output after errors.
- After successful syntax parsing, the compiler validates every call against `BaseData.cmdDic` (including registered aliases) and `ProgramDataForm.DataByName`, using the same case-sensitive lookup as the interpreter. Missing methods produce `方法检查` diagnostics naming the identifier and its source location, with no executable output. Nested and unreachable calls are checked too; strings and member names are not calls. Skip this phase when syntax errors already exist so recovery does not add misleading diagnostics. Register all custom programs before compiling a batch, as `LoadEvent` does, to allow forward and recursive references. `TryApplyCode` keeps the last valid program untouched on a missing-method error.
- Function arguments bind in source order; expression statements must leave the stack balanced.
- Cmd calls may omit trailing arguments, and explicit empty slots such as `Cmd(,value,)` are preserved. Each omitted Cmd argument reaches `ExecuteInternal` as an empty-string Box; excess arguments remain an error. Custom stored-program calls keep exact parameter-count validation.
- `ShowDialog` has ten canonical parameters: background, avatar, title, content, optional audio, and five optional illustrations from left to right. Four- and five-argument calls remain valid because omitted trailing parameters are padded; stored event files do not need migration.
- Event-editor Cmd parameter replacement compiles one expression as a temporary terminated statement. Add the missing trailing semicolon only in that single-node editor path; complete stored event programs continue to require explicit statement terminators.
- Event-editor Item creation/insertion compiles the chosen command's table `defaultCode` as a complete statement. Every independently callable `void` command default in GameCmdData must include its trailing semicolon in the Excel source; `if`/`for` blocks are the exception. Keep this contract in the table rather than adding a generic terminator in Item UI. Do not relax the full stored-program compiler's semicolon requirement.
- Recompile each complete ef record from source after code-generation changes. Keep zCode and zCodeMap counts equal. A migrated ef record may temporarily store both caches as empty; `GameSaveController.LoadEvent` recompiles it from source after registering all programs, and the next save persists the rebuilt caches.
- Scene and story trigger arguments use `param1`, `param2`, and `param3` in place of the retired `self`, `target`, and `delta` names. `param1` is the emitting unit/product, `param2` is the touched target, used item, skill, or changed parameter name (depending on trigger), and `param3` is the character-parameter change amount. Program-to-program calls must pass needed values explicitly; subprograms do not inherit the trigger heap. Loading an older ef recompiles standalone legacy identifiers from source while leaving string literals unchanged.
- Clicking a Play interaction option (`onInteractEvent`) passes the interacted Character as `$ch$ProductUid$ch$` in `param1`, not its scene Unit UID. Objects and other non-Character MapUnits keep `$so$UnitUid$so$`. `param2` remains the current player's Character Product reference; the event owner remains the interacted scene Unit UID/Data identity independently of the argument's reference type. Collision touch/leave already use this typed Character/non-Character distinction; do not alter the separate BoundaryTouch scene-reference contract.
- `onTileTouchEvent` is a unit-owned scene trigger fired when a moving MapUnit enters a Tile physical Collider. Its heap exposes the moving unit as `param1` and the Tile as `param2`, both using the existing scene-object handle format; map-edge contact remains `onBoundaryTouchEvent`.
- Deferred MapUnit lifecycle callbacks such as `onShowEvent` and `onBoundaryTouchEvent` must verify that the original unit data is still registered in `UnitForm` by both UID and reference identity before dispatch. UID equality alone is insufficient because removed unit IDs can be reused.
- Removing an ObjectUnit immediately marks its other active scene-trigger interpreters and their polled asynchronous tasks as cancelled, and releases their `OnceDuring` and blocking state. The interpreter currently performing the removal may finish only its current `Interpret` pass; after it returns to the event scheduler, it and its tasks are cancelled before another pass or task poll. New and resumed events validate the original `UnitForm.Data` reference as well as the UID so UID reuse cannot revive stale work.
- Every polled task started by an event is owned by that root `EventInterpretData`, including tasks started inside subprograms. Normal completion, cancellation, and scene/controller clearing must cancel all owned tasks before removing the event, so no task may outlive its event.
- A pending Cmd captures its call PC/name, argument count, declared return count and discard mode once. Waiting/completion polls must not recreate the command, allocate another argument array, resolve arguments again or re-read changed command metadata/registries. Validate results and balance the stack using the captured counts. Reset permits a new invocation; cancellation remains event-owned. A suspended custom program likewise resumes its captured program/signature rather than re-resolving a changed/removed registry entry or a newly registered same-name Cmd.
- Published compiled `zCode` and `zCodeMap` lists are immutable, including raw-bytecode fixtures and runtime snapshots. Build a new list before publishing any change; never change elements, counts or ordering in place. `TryApplyCode` and repeated Compiler use already produce replacement lists. `ProgramDataForm.Data.CreateRuntimeSnapshot()` preserves the concrete metadata type and captures private code/source-map lists once per authored revision. At new event/subprogram startup, only reference identity determines whether either source list changed; no content scan or in-place edit support is needed. Unchanged executions share the private lists, not their metadata wrapper, PC, stack, heap or task. Active snapshots continue their old revision after replacement. Current EventProgram derived metadata adds only scalar `labId`; explicitly snapshot any future mutable derived fields. Parsed opcode/numeric/integer arrays are weakly cached by immutable compiled-list identity, without token-change checks; Reset releases local views without invalidating other interpreters. Do not key caches by recyclable program UID or persist them into Forms/saves.
- RetInfo's public default construction still supplies an independent empty Box and error list; internal construction with a supplied return value must not first allocate and discard another default Box. Arithmetic already creates independent scalar/dictionary results, so `+=` stores its new result without another deep copy; ordinary assignment and subprogram argument copy-in/copy-out semantics stay unchanged.
- Scalar/string/reference factories leave `Box.dic` null (an empty dictionary); `DeepCopy` preserves this lazy state. `CreateBox` remains the writable-container factory. Use `GetOrCreateDictionary` when accessing/writing members. `GetBox` does not initialize dictionaries for scalar reads; CmdBase materializes each resolved argument's root dictionary for existing command implementations.
- All Interpreters share one main-thread pool of private temporary scalar/reference Boxes, capped at 128 free entries globally. Only free Boxes are shared; current ownership and deferred-consumption lists remain per Interpreter. Return clears owner/value/dictionary references so the static pool cannot retain an Interpreter or its scene/heap; rent assigns the new owner. SubsystemRegistration clears the free pool for a new Play lifetime, including when domain reload is disabled; individual Reset/Cancel do not clear other Interpreters' free entries. Pop/Pop2/PopMany defer recycling until the instruction's finally block, after all operands are consumed; instructions with no consumed Boxes skip the recycler call. Wait's repushed countdown and budget-suspended stack values stay live. Heap/dictionary results are independent nonpooled Boxes; scalar arithmetic used for `+=` and dictionary fields creates owned results directly. Export to a command or RetInfo permanently detaches a temporary from its pool before exposing it, so synchronous/asynchronous command captures and retained returns cannot be overwritten by later instructions or executions. Reset/Cancel detach outstanding stack temporaries without mutating their contents. Never recycle arbitrary heap, dictionary, command or return Boxes, clear a shared copy-out dictionary, or share a live literal across interpreters.
- The pool initializes/clears its private unregistered TemporaryBoxes through `BoxDataForm.Data.InitializeTemporaryValue/ClearTemporaryValue` in the hand-written partial, accessing backing fields directly. These internal methods must never be used on ordinary/registered/escaped Boxes; their generated setters, indexes and notifications remain authoritative. `Pop2` validates both inputs once, reports null/underflow before removal, removes the tail in one batch and updates top once. Intrinsic results use `PushResult` after that validated pop, while ordinary pushes at startup/call boundaries retain validation. Arithmetic resolves root operands once at entry and dictionary children once per recursion; already-resolved scalar/broadcast operands are not passed through GetBox again. Preserve operand order, string formatting, fresh dictionary results and division/modulo-by-zero diagnostics.
- Event scheduling reuses a frame-start snapshot and ignores reentrant LateUpdate calls; events created during the current pass execute on the next pass. Tasks are indexed by root event and scene-owner Data **reference identity**, and indexed cancellation must not affect reused UIDs. Stable task compaction preserves task callback order and the existing same-pass polling of appended tasks. Scene/reset lifecycle changes invalidate the old compaction pass so callbacks cannot reinsert old work or discard replacement work. Exception cleanup preserves unpolled tasks and releases the reentrancy guard. Keep the current-removing-event pass exception and root ownership of subprogram tasks.
- An Item Product's `onUseEvent` is dispatched when the backpack uses that item. Its heap exposes the current Character Product as `param1` and the used Item Product as `param2`; execute it with the used Item Product UID as the trigger owner so per-owner trigger modes remain isolated.
- The `SceneObject` chooser selects an authored ObjectProduct (`protoUid=0`) and writes `$so$p:ProductUid$so$`, the same marker used for concrete runtime Products. Prototype handles fan out; runtime handles target exactly. Generated objects and object event/interaction arguments return precise Product handles. Bare `$so$UnitUid$so$` retains legacy scene-unit semantics (including Items/Tiles/Characters). Old `$so$t:MapObjectId$so$`/`$sop$MapObjectId$sop$` references are mapped at legacy load and rewritten in saved event/progress strings; new code never depends on transient MapObject list IDs. `SceneObjectProto` remains a runtime method alias without its own chooser/type. `GenerateObject` deep-copies an existing runtime Product when used as input, rather than sharing mutable state. `Item` still writes `$it$ItemProductUid$it$`.
- `$ch$CharacterProductUid$ch$` accepts both concrete runtime Products and authored prototypes. Runtime Products resolve exactly; prototypes expand their runtime copies, with authored unique Characters retaining singleton identity. Scene-unit mutations (position/move/rotation/navigation/animation/destruction/chat/effects) snapshot all matching live instances. Parameter mutations address matching stored runtime Products too, including unloaded scenes, without mutating non-unique authored defaults. Scalar/vector getters retain one return value: first live Unit by ascending Unit UID, otherwise first stored Product by ascending Product UID, otherwise read-only authored defaults. Missing/malformed references no-op or return the command's existing empty/zero value. Always capture original Unit Data identity for asynchronous work so a recycled UID cannot revive or retarget it.
- Mission parameters use the `mission` entry in `GameCmdTypeData_CmdTypeData.xlsx`, not plain `string`. The `Mission` constant chooser writes a quoted `$m$id$m$` reference using `MissionForm.Data.id`; its empty default is `"$m$$m$"`. Keep both its `retNames` and `retTypes` populated so direct `Mission()` calls return one value too. Edit the Excel sources and regenerate only the two affected GameCmd Forms.
- The `Mission` constant belongs to the canonical basic/constant Lab `10001`, alongside `Text`/`Num`, and uses the existing `mission` translation key for its chooser label. Mission operations remain in Lab `10015`. Both `mission`-typed and generic `var` argument choosers must expose this constant exactly once, then select from `MissionForm.DataById`, not asset or unit Forms.
- Canonical mission commands are `AddMission`, `DoneMission`, `IsMissionAdded`, and `HasMissionDone`. Registration, table names and default calls must match; preserve `MissionAdd`, `MissionDone`, `CompleteMission`, and `IsMissionComplete` as runtime aliases that resolve canonical metadata. Wrapped IDs survive mission renaming; old plain mission names remain accepted for existing stories. Empty, malformed, removed and missing references are no-ops for mutation and return `0` for queries. Add/Done events fire only on actual state changes.
- `GetCharacterName(character)` resolves a `$ch$uid$ch$` Character reference and returns the owning `CharacterProductForm.name`; an invalid reference returns an empty string.
- The `character` CmdLab (`10007`) also exposes `AddCharacterToTeam`, `RemoveCharacterFromTeam`, `DeployCharacter`, `UndeployCharacter`, and `SetCurrentCharacter` (UIDs `100112..100116`). Each takes one `character` reference and returns void. Membership changes go through `ExternalPlayInfoController`, preserving current ⊆ active ⊆ team, ordered duplicate-free lists and idempotent notifications. Deploy joins first; removing from team undeploys first; switching joins and deploys before selecting. Removing/undeploying the current Character selects the first remaining valid active member or clears the current UID to `0`; it never deletes a Product. The four membership operations fan out prototype references; current selection keeps an already-current match, otherwise uses the normal scalar representative. Recruiting/deploying/selecting a non-unique prototype with no runtime copy creates one runtime Product through `ToProduct`; removal/undeployment never creates one. Empty/malformed/missing references no-op. These additions use existing Progress team fields and require no save-schema migration.
- `GetCurrentCharacter()` returns an empty string when the Play scene has no current player character (`characterUid=0` or a missing Character Product), rather than dereferencing a null player.
- `SetCharacterNavigate` and `SetCharacterNavigateRelative` use the Product's bound `speedParamName` only when its parameter exists and is non-null. An empty/missing binding or parameter dictionary preserves the scene Character's current `speed`; it does not guess a `Speed` key or modify authored bindings. Destination conversion and Product `enableNav` remain unchanged.
- `DestroyCharacter` accepts both `$ch$ProductUid$ch$` and a Character's `$so$UnitUid$so$` (used by interaction/BoundaryTouch `param1`). Remove the live scene instance synchronously through Play/Map ownership, clear its lookup/player references and interaction option, and cancel its other scene events/tasks using the same removal contract as Objects; the removing event may finish its current pass (including a following Continue). Unique Products survive scene removal; non-unique Products are removed afterward. Missing, already removed or non-Character scene references are no-ops, and lookup/removal checks original Data identity so recycled UIDs cannot revive stale instances.
- `Random(num1,num2)` returns a deterministic integer-valued `num` in the inclusive integer range covered by its two arguments. Decimal bounds are rounded inward (`ceil(min)` and `floor(max)`); it hashes the current `StoryForm.randomSeed` together with the exact `ProgressForm.seconds` float value, reversed bounds are normalized, and identical seed/time/bounds produce the same result.
- `GetLookAtRotation(from,to)` returns horizontal world yaw: `0°` toward positive map Y/Unity Z, `90°` toward positive map X, normalized to `[0,360)`. Ignore height; apply the map's horizontal unit sizes to the position delta before computing the angle. When horizontal positions coincide, return `0°` instead of asking Unity to rotate toward a zero/vertical vector.
- `SetRotation(unit, angle, transitionTime)` belongs to the `scene` CmdLab (`10026`) and accepts both live `$ch$ProductUid$ch$` and `$so$UnitUid$so$` Character/Object references. Positive transition times wait for constant-rate shortest-path interpolation (including `0°/360°` wraparound) to reach the exact target yaw; nonpositive times update Data and the visible instance in the same call. Preserve X/Z Euler components, synchronize Character `forceEuler`/overlap coverage, and retain Object `ApplyMove` plus Move appearance notification for directional textures and collision/navigation footprints. Capture the instance/scalar arguments, stop when its Data identity is removed/replaced, and no-op for invalid references or nonfinite arguments. `SetCharacterRotation` and `SetObjectRotation` remain runtime aliases using canonical metadata, not duplicate chooser rows; both now use the same waiting/shortest-path behavior.
- Object/Character timed movement and rotation use `MapUtilController.MovementDeltaTime` (forwarding to `Z_Time.TimeManager.GetDeltaTime()`, scaled frame delta capped at `0.02` seconds) for both interpolation and duration consumption. Stalls intentionally slow them like keyboard/touch/navigation movement; discarded time is never accumulated or caught up later. Command duration is bounded game time, not wall-clock time. Interpreter `Op.Wait`, game seconds/cooldowns and scene shake also consume the shared bounded step; keep instantaneous positioning/rotation and absolute-time scheduling unchanged. ObjectAnimator explicit frame waits retain frame counts rather than converting through a possibly zero delta.
- The `scene` CmdLab exposes `GetPosition(unit)`, `SetPosition(unit,pos)`, `GetPositionRelative(target,origin)`, `SetPositionRelative(unit,offset)`, `Move(unit,pos,speed)`, `MoveRelative(unit,offset,speed)` and `SetRotation(unit,angle,transitionTime)`. Resolve live `$ch$ProductUid$ch$` and `$so$UnitUid$so$` references through one scene-unit helper; query scene MapUnits, but mutate only Character/Object units. Missing references return zero vectors or no-op. Absolute coordinates convert player coordinates (+500) before map-unit scaling; relative vectors have no origin offset. Relative Get returns target minus origin, and relative Set/Move use world axes from the unit's initial position. Set uses teleport-style ApplyMove so Data/transform/spatial indexes agree immediately.
- New Move commands take positive speed in logical 3D tiles/second, never multiply by Character Speed, normalize in map units and convert each bounded frame displacement to world units before Unit.Move. Keep physical/pass/boundary/trigger rules. End at arrival or after initial distance/speed bounded game time when obstructed, avoiding indefinitely blocked events; nonpositive/invalid speeds no-op. Capture the original Data identity and end if removed/replaced; never re-resolve a recycled UID or share interpreter heapTemp between tasks. Stored `Get/SetCharacterPosition`, `Get/SetObjectPosition`, and existing relative names remain runtime aliases using canonical metadata. Old `MoveCharacter[Relative]`/`MoveObject[Relative]` aliases retain their third-argument duration; only new Move names use speed. Editor description/argument lookup resolves aliases while preserving old source and duration semantics.
- `SetLightIntensity(intensity)` belongs to the `scene` CmdLab (`10026`, uid `100111`) and sets `CameraInstance.globalLight.intensity` immediately, clamping negative/nonfinite arguments and treating an empty argument as a no-op. It also records the value in `ProgressForm.lightIntensity` (`float`, default `-1` = never set), so a level's lighting survives scene changes and saves; `GameManager.ApplyProgressLightIntensity()` re-applies a nonnegative recorded value after the Play/Mod `Begin` camera-mode defaults (`1`/`1.3`) and inside `LoadProgress`, while `-1` keeps those defaults. The argument lives in `GameCmdData_CmdData.xlsx` and regenerates `GameCmdDataForm.cs`; adding the field also makes `ProgressForm.Data(...)` one parameter longer at its single call site in `Main2StoryManager.StartLoadStoryUgc`.
- `SceneShake(seconds)` launches a nonblocking visual task: the interpreter continues with the next statement immediately while the CameraInstance-owned runner shakes for the requested duration. Omitted seconds preserve the former one-second default. The runner offsets the camera child horizontally by up to `0.08` world units and an active DialogBg by up to `10` anchored UI units, completing two left-right cycles, then restores both positions. A later shake replaces the earlier one; scene change or disable restores positions too. Do not move CameraInstance's clamped target/root position.
- `IsUnobstructed(from,to,radius)` treats any `CollideOnly` Tile hit and any collidable Object hit as obstruction; non-obstacle Objects and Characters do not block this command. Its `CaptureCast` candidate scan covers the whole swept segment and every Tile layer in each crossed X/Z column, while the actual Mesh sweep decides whether a candidate is hit.

## Limits and validation

The runtime budget is 4096 instructions per top-level call, child depth is 64, and source/AST depth is 256. Build Z_Code and Z_Code.Tests.Editor. `Docs/Tests/Run-MapRuntimeRegression.ps1 -Fixture CodeInterpreterRuntimeRegression` runs the real NUnit assertions (including saved ef compilation) on Unity Mono in a separate temporary project using cached NUnit; no production scene/save is modified. `MapRuntimeRegression.RunInterpreterSchedulingOptimization` isolates frame snapshots, task ownership/compaction and lifecycle regressions, and is included in the full map fixture. Run Tuanjie EditMode tests when licensed; source/code-generation changes still require recompiling every persisted ef source.
