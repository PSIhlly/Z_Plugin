## Shared movement and interaction pipeline

```text
CharacterUnit.Move(dir)
→ inspect nearby tiles and units
→ MapUpdateController.CheckCollide(..., CollideOnly)
→ Mesh.MeshIntersectMesh
→ Graph Sphere/Cube intersection
→ truncate movement and possibly enqueue slide movement
```

Interaction uses the same geometry with `TriggerOnly`, then defers Enter/Exit/Cross effects through the map update lifecycle.

Movement uses `MapUtilController.MovementDeltaTime`, forwarding to `Z_Time.TimeManager.GetDeltaTime()` with a `0.02`-second cap; `GlobalSettings.MAX_MOVEMENT_DELTA_TIME` aliases `TimeManager.MAX_DELTA_TIME`. Keyboard/touch displacement, Character navigation/escape/gravity, and Object/Character Move and timed rotation commands share it. At normal frame rates use the actual scaled delta; below 50 FPS movement slows instead of increasing its per-frame jump. Drop excess stall time without an accumulator or FixedUpdate catch-up. Timed movement/rotation must advance and decrement their remaining duration with the same bounded step, so a stall cannot expire them before they move. Progress/cooldown/UI clocks that consume frame delta also use this shared cap, retaining their original blocking/pause guards; pause-independent input drag scrolling requests bounded unscaled time. Preserve explicit teleport/displacement APIs, absolute-time timers and Unity's global time settings.

Preserve the semantic split:

- `CollideOnly`: physical obstacle meshes (`isTrigger=false`).
- `TriggerOnly`: event trigger meshes (`isTrigger=true`).
- `All`: explicit callers that need both.

## Non-negotiable collision invariants

- Keep the bounded nearby-tile traversal and the current lower-layer skip rule.
- Do not reject collision candidates by Tile-anchor distance. A Tile Collider may cross logical layers (notably `mapground` extending downward); the actual `CollideOnly` Mesh AABB/SAT result is authoritative.
- `CaptureCast` gathers candidates across the complete swept segment, not only endpoint cells. In each crossed X/Z column it checks every registered Tile height, because a higher Tile's physical Collider may extend down into the queried ray height; `CollideOnly` Mesh sweep remains the final hit test.
- Merge avoidance normals through `MergeAvoidDir` / `MergeAvoidDirRange`; do not replace them with blind `AddRange` or averaging.
- Compute sphere-versus-OBB separation and push direction from the OBB closest point at contact. Do not substitute an AABB closest point for rotated/sloped boxes.
- Use AABB only for broad-phase rejection where the current algorithm does so.
- Preserve axis deduplication and the nearest-point separation axis that prevents corner false positives.
- Keep `GetPushDirByFace` only as the existing degeneracy fallback; it previously chose the wrong face at corners.
- Preserve the movement queue and first-attempt guard that bound repeated slide attempts.
- Character movement accepts unobstructed steps smaller than `0.01` world units, so scaled high-FPS keyboard/navigation movement cannot stall at low speeds. Keep the existing `0.01` contact dead zone for collision-truncated steps; full steps require `res > 0.000001` and `res >= requestedMagnitude - 0.000001`. Zero/near-zero requests remain ignored.
- Do not erase positive Y slide/climb components through unconditional tile snapping.
- For non-player character auto-facing, accumulate actual horizontal movement across `Move` calls. Update toward the latest actual movement direction only after the total is strictly greater than `abs(speed) / 3`, then reset the accumulator; blocked or vertical-only movement keeps the prior facing, and `forceEuler` resets the accumulator.
- Apply gravity only when `HasGroundContact()` is false; preserve the lower-contact threshold and tolerance unless the whole grounding model is retuned.
- Preserve `IntersectType` meanings: `None`, `In`, `Out`, `Cross`, and `Inner`.

## Trigger and ownership rules

- Maintain `Unit.collidingUnitUid` so Enter/Exit is not emitted repeatedly.
- Defer managed trigger events as the current `MapUpdateController` expects; do not mutate map collections while collision enumeration is active.
- During non-teleport movement, test each moving MapUnit against candidate Tile `CollideOnly` meshes and route contact state through the same deferred `Unit.OnEnter` / `Unit.OnExit` pipeline. On Enter, the moving unit executes `onTileTouchEvent`; this is distinct from map-edge `onBoundaryTouchEvent`.
- Treat teleport movement separately: `ApplyMove(..., teleport: true)` skips movement Trigger sweep entirely.
- Move and pool entities through Map/Unit ownership. Do not permanently instantiate parallel objects outside `InstancePoolManager`.
- Update tile association through the existing `ApplyMove` flow so spatial lookups, data position, GameObject transform, and triggers remain synchronized.
- `GetPlacementTile(worldPosition)` uses the existing `RealPos2MapPosInt` conversion (including map-unit dimensions and logical-coordinate rounding), then `GetTile` for exact-layer/nearest-lower lookup in that X/Z column. Mod Object/Item/Character placement is not capped at the next/highest Tile layer and rejects only when that column has no Tile at/below the target logical layer; preserve the requested world height. Object visual associations put that support Tile first for stable `belongTile`. MapManager Item/Character creation must register the resolved Tile instead of indexing a missing exact-layer key; retain the Character runtime nearest-area fallback, but Mod prevalidation rejects unsupported columns before reaching it. Load, teleport and row-local undo/redo use the same lower-owner association without height snapping.
- ModScene Object picking is separate from lower-owner association: normal/Event clicks first skip an owner above the camera target's editing plane, or an Object whose active/enabled physical Colliders are all strictly above that plane (`bounds.min.y > planeY + 0.0001`). Read live world Collider bounds to include model offsets, rotation, scale and texture fitting; do not use root position or padded Triggers when physical bodies exist. A body touching/extending below permits selection, and Trigger-only prefabs use the hit Collider's bounds. Prefer any eligible target behind skipped Objects; if the click finds no eligible target, fall back to the first skipped Object in the existing near-to-far (top-down) ray order. Event Tiles count as eligible targets, while normal mode ignores Tiles. Do not change ownership, placement, erase, or Play geometry.
- Keep `characterTileDic` as the single owner/support association used by `belongTile`, visibility, fog, and editor placement. Keep broad-phase character coverage in `characterOverlapTileDic`; only register characters that already have an owner, refresh after add/load/move/rotation/scale changes, and clear on remove/end.
- Refresh character coverage by comparing the full queried footprint with existing links: remove departed Tiles and add newly covered Tiles in both directions. Do not delete/rebuild unchanged links or use center-cell changes as the refresh condition.
- Derive character broad-phase candidates from the actual `CollideOnly`/`All` Mesh swept AABB. Movement, grounding, trigger scans, CaptureCast, and object pushing must query the overlap index rather than assuming the owner Tile contains the whole character.
- `CharacterProductForm.size` drives `CharacterUnitForm.scale = Vector3.one * max(1, size)`, so model, physical Collider, Trigger, overlap index, and navigation clearance scale together.
- `GameUtilController.CombineNewCharacterByPrefabs` sets the base physical SphereCollider radius to `0.4`; character sizes `1`, `2`, and `3` therefore have world radii `0.4`, `0.8`, and `1.2`. Navigation derives its radius from the physical mesh rather than a separate fixed value. The base sphere Trigger radius is `0.6`; sphere Renderer size is independent of the physical Collider radius. `CombineNewGoByPrefabs` adds `0.1` to each full BoxCollider size axis, divided by the model's corresponding lossy scale, and adds `0.1 * max(lossyScale)` to a SphereCollider radius. Thus unscaled built-in Cube/Sphere models generate Trigger edge lengths `1.1` / radius `0.6` before subsequent per-unit scaling or texture fitting. Unit Trigger events compare both units' `TriggerOnly` meshes, so contact range includes the moving unit's Trigger footprint.
- Before applying non-teleport character movement, clamp the target center inside the map's horizontal outer boundary by `max(1, CharacterUnitForm.scale.x) * 0.2`, matching `CharacterProductForm.size * 0.2`. Search across contiguous walkable Tiles when the inset spans multiple cells. Use the same distance for character `BoundaryTouch`. Object movement does not use a fixed inset: emit Object `BoundaryTouch` only when the requested target center actually touches or leaves the map area. General `InArea(Vector3)` checks retain the base `0.2` inset unless the caller explicitly supplies another distance.
- Navigation remains a shared center graph, but each character query supplies its actual horizontal Collider radius. Validate every footprint offset transition and expand path smoothing by the same clearance; size `1` must preserve the base graph behavior.
- Editor Play navigation debug is enabled by `PlayManager.showWalkableNavTiles` (Inspector default on; Scene Gizmos must be enabled). Its `OnDrawGizmos` reads the live Nav graph and draws green Tile outlines 0.1 world units above cached terrain, including slopes. With a player it reuses `Bfs.IsWalkable`, the player's physical navigation radius and pass types; without a player it shows base graph walkability. This is node walkability, not reachability from the player. Never rebuild navigation or instantiate runtime renderers for this overlay; it is excluded from player builds.
- Each Character owns a non-serialized `NavigationEndpointState`, including pending search buffers and its last completed waypoint. BFS, blocked-start nearest-anchor scanning, backtracking and smoothing share a budget of `Bfs.CellsPerFrame = 10` cell work items per Character per real frame; repeated same-frame calls or resets do not grant extra work. `maxStep` remains a separate graph-depth limit. Publish only a completed round, recompute direction from the current position to the cached waypoint while the next round is pending, and begin that next round on the next frame. The first round waits without activating stuck-side-stepping; reaching the cached waypoint before its replacement is ready also waits. Rebase a completed route against the actor's current path cell, discarding a candidate if it has moved off that route. Ordinary target-cell changes retain the captured in-flight round and prior waypoint so moving targets cannot starve completion; the next round captures the newest destination. A cached target-following shortcut tracks only within its captured destination cell, never across cells.
- An invalid/blocked/pass-restricted start first moves straight to the nearest walkable cell center (including physical footprint clearance), keeping that anchor until arrival. An invalid destination routes to the closest **reachable** walkable cell, then approaches the original world coordinate directly. Keep the final phase after entering a blocked cell; otherwise it oscillates back into start escape. Normal disconnected-but-walkable destinations keep the existing unreachable fallback. Neither a pending frame budget nor exhausted graph depth permits the final segment. Endpoint moves alone bypass terrain pass-type clamping; physical collision, Trigger sweeps and map boundaries stay active. Manual movement remains pass-restricted. Bound each frame's displacement by the current waypoint, not just the final destination. Fully reset when navigation stops, radius changes beyond `0.0001`, pass capabilities/controller change, or on teleport. Target-cell changes clear the old final direct phase/result, and obsolete captured rounds cannot publish a final direct leg; same-cell target movement uses the newest coordinate. Reuse a still-valid start anchor instead of rescanning every escape frame. Applying equivalent Character pass types (ignoring order, duplicates and zero) must not reset navigation; normalize product pass types only when their content changes.
- In BFS reject visited neighbours before traversal tests, prepare each source footprint once per expanded node, and use the known-link fast path only for neighbours read directly from that node's links. Public `CanPass(from, target, ...)` must retain arbitrary-edge validation. Skip the zero footprint offset after validating the center, use indexed offset/link loops rather than boxed interface enumerators, and reuse per-agent containers. Smoothing retains its expanded physical rectangle and directional edges; pass types constrain only the center line. If all checked rectangle cells accept the Character's pass types, skip redundant center-line rescans; otherwise retain the exact center-line test without rejecting restricted neighbouring footprint cells. Do not allocate debug path arrays. Actual Nav dictionary membership changes increment `LayoutVersion` and restart pending rounds before a suspended enumerator resumes; ordinary periodic value/link refreshes do not restart long searches.
- Object changes must use local Nav updates, never synchronous full-map rebuilds: reset only old/new footprint cells from cached directional ground heights, reevaluate overlapping obstacles and effective pass types, then rebuild their outgoing links and the adjacent cells' incoming links (four horizontal directions, Y offsets -1..1). Reuse local work sets and pass-type containers; do not resample unchanged terrain or scan every Object/Tile. Retain the last completed solid-terrain blocked set, and replay only Object-dirtied cells after an existing periodic full-build coroutine finishes. Full rebuilds remain for scene setup and the established periodic/explicit map refresh paths.
- Terrain pass requirements come from the three MapTexture IDs already persisted in `TileUnitForm.texDic` slots `0..TERRAIN_LAYER_MAX-1`. On scene entry, resolve each texture's nonzero `MapTextureForm.passType` into `TileUnit.passTypes`; `TileUnitForm.passType` remains the authored compatibility/cache field. When the vertical segment from `tile.data.pos` through `tile.data.pos + Vector3.up` intersects an Object body, its effective runtime `TileUnit.passTypes` is empty (default) without erasing the authored terrain requirements; after the last covering Object leaves, the original requirements apply again. The probe spans **0..1 world units inclusive**, not one logical layer, not a horizontal projection, and not an infinite ray. Copy the effective set into `NavUnit.passTypes`. Object add/remove/move/rotation and explicit footprint refresh must reevaluate both old and new covered Tiles, then complete Nav graph/obstacle refresh before returning. A character may enter or route through a Tile only when its runtime set, rebuilt from `CharacterProductForm.passType`, contains every required ID. Pass requirements use only the Tile containing the character/navigation center; character size, Collider/Trigger footprint, and navigation-clearance offsets do not add pass requirements from neighbouring Tiles. When a manual movement target belongs to a disallowed Tile, use the pass-aware closest-existing-Tile search to place the center at the nearest legal position. `0` never adds a requirement.
- Keep Object pass-type coverage in the separate `objectPassTypeTileDic` exact-hit index. Prefer cached `GetMeshes(CollideOnly)` bodies, including `MapModel.colliderScale`, nested transforms, Collider centers and saved root transforms; enlarged Triggers never expand pass coverage. Enumerate each physical body's local AABB expanded downward by the 1-world-unit probe, then use segment/box SAT or segment/sphere distance for exact hits. Sphere radius matches the existing physical collision conversion. Only prefabs without supported physical bodies retain the prior centered-model/Renderer/anchored-box fallback. Combined fallback bodies use each direct child's actual `localPosition`, already including the +0.5Y placement; never subtract that pivot offset. The visual/owner index remains independent of `colliderScale` and must not be expanded to implement pass probes. Local Nav refresh uses the union of old/new visual, pass-probe, and physical-navigation cells. End clears both dedicated indexes and transient Tile overrides.
- Object navigation uses the same cached `GetMeshes(CollideOnly)` Box/Sphere bodies as physical collision, including collisionScale, nested transforms, Collider centers and saved root transforms; Trigger padding is excluded. Keep their conservative cell coverage in `objectNavigationTileDic`, independently of visual/owner and pass-probe indexes, including before Play enables `isObstacle`. Full and local updates share `TryGetObjectNavigationRange` and separate central standability from four directional edges. `NavUnit.objectBlocked` checks the world-space `0.8 x 0.8` square centered at the Tile; `objectBlockedDirections` stores Right/Left/Forward/Back bits from four inward strips of depth `0.4`, whose long side spans the entire corresponding Tile edge (`1 x 0.4` on unit cells, including corners). An edge exists only if both centers are standable and neither source's outgoing strip nor destination's opposing strip is blocked; retain the independent directional step-height condition. An obstacle's intersecting body portion must rise strictly more than `0.3` world units above that location's cached Tile ground plane; equality remains passable with `0.0001` tolerance. Clip all Box faces to each region with reused buffers; solve Sphere height over the clipped footprint using the physical radius. AABB overlap alone, boundary-only contact and zero horizontal bodies do not block. Height outside the tested region is irrelevant. Keep the existing Tile ground samples, never Object tops. A center with no outgoing links is still standable, not a blocked-start/target endpoint exception; retain explicit solid-mapground blocking in base/BFS walkability. BFS footprint transitions consume the actual directional links, and smoothing requires internal links in its expanded rectangle so it cannot shortcut edge barriers. Object changes reset/recompute central and edge flags only for old/new covered cells, preserve other overlapping obstacles and refresh adjacent incoming edges; no full-map scan/rebuild or per-cell geometry allocation. Removal refreshes the old physical footprint too. Conservative navigation ranges cover the central 0.8 square even on cells narrower than 0.8; other visual/pass ownership remains unchanged.

## Map resource contracts

Play periodic navigation rebuilds use `max((TileCount * 3 + ObjectCount) / 100, 5)` work items per frame (half the previous `/50, min 10`); scene setup and explicit `RebuildNow` remain synchronous. `UpdateMap` skips requests while a full coroutine is active because its work buffers are shared. Object central/four-edge checks prepare the ground plane, body bounds/height or physical Sphere radius once per body/cell; skip already-blocked directional bits, but keep accumulating unblocked bits from overlapping bodies. Flat-ground, exactly axis-aligned Boxes use strict rectangle overlap and the same height/projected-area threshold as an exact fast path. Near-axis/rotated/sloped Boxes retain face clipping; Sphere clipped-height, `0.3`/`0.0001`, boundary-only and degenerate rules are unchanged. Do not cache prepared contexts across yields or movement. Validate original/optimized equivalence and zero allocations with `RunNavigationOptimization`; profiling real frame spikes remains required.

Built-in map content loads with `Resources.LoadAll("Z_Map/")` from `Assets/Z_Level3/Z_Map/Sample/Resources/Z_Map`.

New maps use `MapMainForm.mapUnitSize = (1, 1, 1)`: adjacent logical Tile Y layers are one world unit apart. Saved `mapPos.y` remains the integer layer index; saved unit `pos.y`, character `destination.y`, progress `pos.y`, and mission `targetPos.y` are world heights. Use `scripts/migrate-tile-height.ps1` to divide those saved world heights and `mapUnitSize.y` by `1.5` when converting an old `(1, 1.5, 1)` story. Keep rotations, model scales/local offsets, and logical coordinates unchanged. The script backs up affected files and refuses mixed old/new scene heights to avoid double conversion.

Preserve identifiers used as parsing and lookup protocols:

- `MapPrefab$...` for built-in map prefabs.
- `MapTexture$...` for named built-in textures.
- `runtime$...` for runtime prefab names.
- Hashed/high-range built-in asset IDs initialized by `GameManager`. The hash is derived from the full resource name, so a `MapPrefab$...` rename changes its runtime asset ID; migrate persisted `prefabName` values and audit any persisted numeric references.
- Built-in terrain choices come from `MapTerrainForm` and resolve through matching `MapPrefab$...` resources. `mapground` and `mapfloor` use `step=0` and ModScene applies them to one tile without direction logic; `mapslope` uses `step=1` and follows the directional slope branch.
- Treat `mapground` as solid volume for navigation: mark other navigation cells whose walkable cell volume overlaps its `CollideOnly` mesh as blocked, while keeping the owning `mapground` cell walkable on top. Cache each `mapground` Tile's covered NavUnit keys across periodic navigation rebuilds; rebuild that entry only when its prefab reference/name, map position, world position, rotation, scale, or map cell size changes. Adding/removing a navigation Tile or moving a navigation-cell center invalidates the coverage cache because it can change another `mapground` Tile's result. Do not apply this solid-volume rule to `mapfloor` implicitly.
- Solid `mapground` coverage retains its separate `0.2` threshold against the lowest sampled ground (or cell center when no samples exist); equality is not exempt. Ordinary Object central/edge blocking instead uses the `0.3` rule above. Physical collision and the separate step/slope link rule are unchanged: compare facing Tile-side samples with `targetHeight - sourceHeight < step`, independently per direction, so links may be one-way (descending without a valid ascending link).
- After ModScene changes a terrain tile's prefab or transform, call `MapUpdateController.UpdateSingleOne` in the same placement operation so the pooled instance refreshes immediately. Collision mesh caching must also invalidate on prefab, position, rotation, or scale changes.
- `MapUnit.GetMeshes` bakes origin-relative geometry for the current prefab/rotation/scale and reuses world Mesh/vertex arrays during translation. World points are recomputed from cached offsets, not accumulated deltas. `UpdateSingleOne` invalidates the geometry explicitly for same-name prefab edits; consumers must treat returned meshes as live, read-only cache data rather than snapshots.
- `TileUnit.GetYByPoint` caches its original Collider-derived height plane; warmed reads only evaluate the existing plane equation plus current Tile Y, without prefab lookup/Collider traversal/trigonometry or managed allocations. Navigation resolves each prefab name once per full pass and resamples four directional ground heights only when the Tile identity, plane version, center Y or zero-scale state changes. Retain `NavUnit.dirGroundY`, `dirMaxY` and pass-type containers across rebuilds; always restore obstacle working heights from ground and refresh effective pass requirements. Prefab-name/reference and Tile yaw changes refresh the plane automatically; `InvalidateCollisionGeometry` also invalidates it for same-name/in-place Collider edits. `RefreshTerrainTiles` explicitly invalidates edited planes, preserving local edit/undo semantics. Do not change the existing slope formula, degenerate fallback, zero-scale `-999`, step thresholds or Object-only refresh behavior. Validate with `TerrainHeightCaching` in the map fixture; real frame-time gains still require Play/Player profiling.
- Collider extraction ignores only the pool template root's inactive state (`CombineNewGoByPrefabs` intentionally disables it); authored inactive children below that root remain excluded. Disabling the template root must not silently replace physical geometry with visual bounds.
- Zero horizontal Box footprint or zero Sphere radius (`colliderScale=0`) cannot clear Tile pass requirements, even when centered on the probe. Zero Y thickness alone remains supported for flat bridges.
- `MapObjectForm.boundsCollision` is opt-in. Both runtime pools and Object appearance previews call the Product overload of `GameUtilController.CombineNewObjectByPrefabs`. Union the normalized pixel-edge bounds of pixels whose alpha is at least `0.3` (8-bit alpha `77..255`), ignoring faint speckles, across each part's texture list (including every composited GIF/WebP frame). Part 0 uses only the active facing's clip: runtime selects with `GetAnimDirection(data.euler.y)`, and previews pass their selected `previewDirection` (default Up for FourDirection, Fixed otherwise). Never union different facings; an explicitly empty clip must not fall back to the model's legacy clip. Preserve authored model/Renderer transforms. Map image width to X and image height to the cube's Y/Z diagonal: a normalized vertical span `h` gives body dimensions `Y*h` and `Z*h`, retaining the authored Y:Z ratio after model/root scaling; do not weight that ratio twice. Offset the center along both Y/Z with the same normalized image-center displacement. Apply existing `colliderScale` to dimensions but keep center displacement in the unshrunk image space, including the actual Collider Y scale for converted Spheres. Preview generation, live refresh and off-screen meshes share `MapUtilController.GetTextureBoundsBox`. Matching automatic Triggers share the fitted center and retain original padding on all three axes. Unreadable Texture2Ds use temporary readable copies without changing source assets; failed reads conservatively retain full bounds. Visual/WangTile ownership remains based on model/Renderer bounds, while physical collision, pass probes and navigation consume the fitted cached meshes. With the flag off, retain the original Box/Sphere behavior.

Cache the per-unit first-part Rect by product/facing/mask (`-1` for ordinary clips), plus per-texture alpha bounds; only first use scans a variant, not animation ticks or repeated movement. When `isWangTile` is enabled, use the current facing's assembled GameTex frames of the actual eight-neighbour mask, never the source quarter atlas or another facing. Scene loading resolves bounds-enabled units after candidate columns are populated, and Mod resolves again after its existing Collider-scale reset to one. Story appearance previews use the selected facing and assemble isolated mask 0 through `TileHelper` when WangTile is enabled. Other model parts retain their own ordinary texture bounds.
- UGC attaches `MapPrefab$mapMark` only to live Object instance roots, at local position zero and local scale one while preserving the prefab's plane rotation. Existing instances are covered on ModScene entry and newly shown/pooled instances on Object Show. Map instances use only the cached, strongly typed `viewRefreshBindings` model-slot list; `Instance.renderers`, Tile's separate Renderer array, `routingRenderers` and `TrackRenderRouting` are removed. On first access, enumerate all model Renderers including inactive children in the existing hierarchy order and obtain/create one target-bound `DisFadeMaterialBinding` for every slot, including null/alternate DisFade/multi-material Renderers, without routing or changing their materials. Appearance, animation, body/front visibility and MPB clearing all address `binding.Target`; never compact the list to DisFade-only slots. Freeze Object model bindings before appending the UGC marker. Reuse audits must not clear/reorder this slot list. Disable/active handoff only marks existing bindings for deferred restoration, never creates components or releases routing. Unit.Hide no longer calls VisOff or ClearRendererProperties; it uses the assembly-safe virtual Instance.PrepareForHide and detaches/pools normally. InstancePool.Fresh calls virtual PrepareForShow before restoring prefab Renderer slots and activating the hierarchy. MapInstance restores deferred recipes using bindings; generic non-map Instances retain their normal pool MPB restoration without a dependency on Assembly-CSharp. Explicit ClearRendererProperties remains available but is not ordinary Hide work.

Active-reuse component discovery keeps Transform and PerspectiveKeeper in separate typed lists, never a heterogeneous `List<Component>`. Refill these audit lists including inactive children. Inspect each GameObject's component slots with `GetComponentCount`/`GetComponentAtIndex` to preserve the exact whitelist and detect missing scripts, native/custom additions, subclasses and nested Tile instances without allocating component arrays. Additional Renderers/bindings outside the frozen model-slot list must also fall back to native disable/enable, so skipped callbacks cannot strand their material state. Preparation iterates the cached binding list and typed keeper list directly; other component types require validation only, not retained mixed storage.

DisFade material caching is two-level: `sources[originalMaterial]` owns one `SourceMaterial` snapshot and its Texture-to-variants dictionary. Capture the five instanced scalar defaults, render queue and two color-pass switches once per source, not per texture or renderer. `materialOwners` resolves an assigned variant back to that source snapshot; never capture a routed variant as a new source because its pass flags may be camera-dependent. Both `Apply(renderer, block, route)` and `SetTexture(renderer, texture, route)` require the caller's explicit Route. `Assign` only retrieves the cached material for that Route and assigns its reference. Routing never reads MPB scalars to choose a Route; `Classify` is removed. `MapInstance` retains its primary/secondary degree and caches the final Route per Renderer slot during visibility updates: hidden or excluded layers use Hidden, every nonzero degree below one (including occlusion degree `0.5`) uses Transparent, and full visibility uses Opaque. Submit `_Show=degree` and `_FadeCenter=0` for every displayed slot; map occlusion no longer uses camera-center gradients or Mixed. The unused per-slot fadeCenter cache is removed; explicit non-map Mixed routing remains available. `GetRendererRoute(index)` reads that cache (Hidden while the instance is hidden); Tile body/front slots remain independent. Character/Tile/Object/Item texture changes reuse this cached Route instead of recomputing it. Show preparation clears the slot Route cache for pooled reuse. Combined model setup chooses a Route from its authored visibility, and effect transitions choose it from their owned clip opacity. Hidden uses an independent cached material with both color passes disabled in split and fallback cameras, avoiding color submission while preserving the source's authored ShadowCaster pass. Hidden materials follow the same original-source/Texture sharing and immutable Texture binding as the visible routes. Routing leaves Renderer.enabled and shadow casting unchanged, so intentionally empty layers stay disabled. Transparent disables `DisFadeOpaque`; Mixed keeps both color passes; Opaque suppresses its forward pass only during a split camera. `Material.SetShaderPassEnabled` and `GetShaderPassEnabled` use the pass's `LightMode "UniversalForward"`; `Material.FindPass` uses its ShaderLab `Name "Universal Forward"`. Setting and reading the same incorrect Name key can agree while native URP still submits the Forward pass, so verify suppression with a native GPU draw, not only the switch getter. Preserve authored pass switches and queues. Validate cached/explicit Route selection, texture replacement, Tile body/front independence and camera cleanup with `DisFadeRoutingRegression`.

Character runtime templates created by `GameUtilController.CombineNewCharacterByPrefabs(..., forGame: true)` intentionally start with both model Renderers disabled. `AnimController.CloseHideRenderer` must assign each Renderer.enabled from its current animation's `partEnable`, enabling configured parts on first Show/reuse and disabling absent parts. Routing and texture replacement do not own this flag. Keep map hiding/opacity in `_Show` with `_FadeCenter=0`; animation part updates must not overwrite those overrides or the fixed Material-to-Texture binding. Validate cloned disabled templates, repeated pool acquisition, both body-part textures and map visibility with `DisFadeRoutingRegression`.

Each generated DisFade Material has one immutable `_Tex` binding after initialization. Only `MaterialVariants.Create` may assign that texture, before publishing the material in `materialOwners`. `SetTexture` replaces `Renderer.sharedMaterial` with the cached material for the requested Texture; `Apply` switches route variants for the same Texture. Never rewrite an existing material's texture or copy another material's properties onto it. Multiple route materials may share one Texture. The routing fixture retains old material references and checks their texture bindings after both route and texture changes.

DisFade routing callers guarantee every non-null source uses DisFadeCode. Do not reintroduce `IsDisFade`, `Shader.Find`, shader-property comparisons or non-DisFade source compatibility into this helper's hot paths. Preserve null/destroyed-source guards, external replacement by another DisFade source and the existing multi-material MPB fallback; shader-type changes are outside this contract. Tests use alternate DisFade materials, null/destroyed sources and multi-material Renderers rather than exercising unsupported custom shader fallbacks.

`DisFadeMaterialBinding.LastAssigned` is the sole last-internally-assigned material reference; `RendererState` must not duplicate it. Normal Apply/Release/Rebind assignments update it together with sharedMaterial. State creation records the currently accepted material, external replacement checks occur before overwriting the reference, and Clear compares against that same binding value. An active internal Rebind must retain its existing state/source snapshot, static template Texture and authored enabled/shadow baseline rather than treating its temporary Mixed assignment as an external replacement. Inactive Rebind still must not create a routing state.

Do not rename these resources as a cosmetic cleanup.

Inactive material-binding owners must remain unrouted during cache retirement: `Rebind` may assign/register their shared Mixed texture material, but must skip `Refresh` until the Renderer GameObject is active in the hierarchy. Preserve authored enabled/shadow values and do not create an inactive routing state. `StartLoadScene` creates the empty, disabled Character template in `ResetPrefabPool` before `MapManager.Begin` calls `End`/`DisFadeRenderRouting.Clear`; routing its `_Show=0` during that Clear would bake `ShadowsOnly` into every later clone as its original shadow mode. Check repeated Clear before first cloning as well as ordinary reuse; clearing only after activation misses this regression.

## Required validation

Object `centerCollider=false` anchors the final physical body's rear to the combined visual model's local -Z boundary, after Collider scaling and optional texture fitting. Preserve X/Y and visual/ownership/WangTile bounds; matching Triggers share the body offset and retain padding. Runtime pools retain centered baselines. `MapUnit` stores the flag with per-unit first-part bounds, and cached meshes/live instances compute the same offset, including off-screen Objects, zero/large Collider scales, root scaling and rotation. Restore baseline Collider transforms before fitting/anchoring on Show or explicit refresh, never accumulate offsets on reuse. Mod's existing Collider scale-one reset remains intact; resolve anchors again afterward. Default/old-save `true` retains centered behavior. Validate with `ObjectRearAnchoredCollider` in the map fixture.

The anchor is edge-to-edge, never center-to-edge: for an axis-aligned Box, `colliderCenterZ = objectRearZ + finalColliderDepth / 2`. A unit model with `colliderScale=0.2` has rear `-0.5` and Collider center `-0.4`, not `-0.5`. The fixture also checks actual transformed BoxCollider corners independently of the cached Mesh conversion, including fitted sizes and repeated live-instance refreshes.

For collision or movement changes, add focused numeric checks where practical and manually test at least:

- axis-aligned wall collision;
- rotated/sloped box collision;
- sphere near a box corner without contact;
- wall sliding and corner blocking;
- ground contact, falling, and upward slope movement;
- overlapping multiple obstacles with conflicting normals;
- Trigger Enter, Exit, Cross, Inner, and teleport behavior;
- tile-boundary movement and map-edge clamping;
- repeated movement across two logical story scenes;
- character sizes `1`, `2`, and `3` against walls, other characters, Object/Trigger ranges, map edges, one-cell gaps, and sufficiently wide navigation routes.

Record before/after positions, `touchTime`, avoidance normals, and `IntersectType` when diagnosing a regression. Do not “fix” one geometry case without replaying the established corner and slope cases.
