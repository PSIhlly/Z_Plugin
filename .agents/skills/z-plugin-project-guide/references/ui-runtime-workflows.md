## Manager and Controller model

Framework types live under `Assets/Z_Level0/Z_DesignStyle/Core`:

- `Z_Singleton<T>`: lazy plain C# singleton.
- `Z_MonoSingleton<T>`: finds an existing component or creates a GameObject/component.
- `Z_Manager<T>` / `Z_MonoManager<T>`: system lifecycle owner.
- `Z_Controller<T>`: plain C# child owned by a Manager.
- `Z_EventHelper`: synchronous static event bus.

Follow these rules:

- Call `base.Init()` when overriding `Z_MonoManager.Init()` and keep initialization idempotent.
- Construct plain Controllers from their owning Manager and pass the Manager to the controller base.
- Preserve the established `InternalXxxController` / `ExternalXxxController` split: Managers call lifecycle-facing internal APIs; UI and commands consume the narrower external API.
- Do not access a scene-configured singleton before its serialized instance completes `Awake`. Auto-creation can yield an unconfigured object.
- Inspect Inspector dependencies before moving initialization. `UiManager`, `MapManager`, and `InstancePoolManager` rely on serialized fields.
- Treat `TimeManager.Awake()` hiding its base method as an existing lifecycle risk when changing time initialization.

## Product runtime flow

Primary files:

- `GameSample/MyScripts/Main/GameManager.cs`: global services and product entry.
- `GameSample/MyScripts/Main2Scene/Main2StoryManager.cs`: story and logical-scene lifecycle.
- `GameSample/MyScripts/Mod/ModManager.cs`: runtime UGC editor.
- `GameSample/MyScripts/Play/PlayManager.cs`: play mode.

The runtime has two product modes:

```text
Mod:  authored Core data → runtime UGC editing → save Core
Play: Core/Save data → Cache logical scene → runtime progress/save
```

`Mod` is not a Unity Editor folder. Keep it Player-compatible.

Play keyboard and touch-stick movement both multiply direction by `MapUtilController.MovementDeltaTime`, not a fixed per-key event distance or unbounded `Time.deltaTime`. This scaled step forwards to `Z_Time.TimeManager.GetDeltaTime()` and is capped at `0.02` seconds, matching map navigation and scripted Object/Character movement: a slow frame slows all movement without later catch-up. `SetPlayerMove` still accepts a displacement and applies the Character speed parameter; player turning uses the same bounded step. Play image animation/removal, chat/toast timers, game seconds/cooldowns and Android rotation hold use the shared bounded scaled clock, retaining existing blocking/pause guards. `Ipt` parent drag scrolling uses `GetDeltaTime(unscaled: true)` to remain usable during pause, with the same `0.02`-second cap.

Android `InputManager` publishes `InputPointDown/Event/Up` with the stable Unity `Touch.fingerId`, not mouse events or nearest-position IDs. Handle Began, Moved/Stationary and Ended explicitly; Canceled, missing touches, focus/pause loss and input disable release captured touches with `InputPointUpEvent.canceled = true`. A still-held finger after cancellation does not restart a gesture until a fresh Began. Do not synthesize mouse events alongside touch events. `UiStickCtrl` subscribes to both event families on Show and unregisters both on Hide, capturing one `(source, id)` until release; another finger/source cannot steal or release that stick. Reset direction and ownership on Show/Hide. Start checks run only at capture; optional `canContinueFunc` checks the active gesture without rechecking start-only skill exclusion/cooldowns. Play move/LightAttack start only with non-null progress and `blockProgramUid == 0`; LightAttack continuation also allows its own selected skill. Blocking/canceled release clears the stick and invokes hide cleanup, never release-to-cast. Axis drag timers use TryGetValue and cancel when their pointer disappears.

InputManager.UICheck skips UI ray hits whose effective IPointerDownHandler implements the lower-layer IInputUiPassThrough contract and currently enables pass-through. TouchPass implements that contract via isActiveAndEnabled. Resolve the actual handler so decorative Graphic children inherit their TouchPass Button, while a nested ordinary Button still blocks. Continue checking lower UI hits; do not disable Graphic raycasts or remove the background Button's UGUI close callback. Mouse and Android touch paths share this check.

ModScene captures the first non-UI touch and routes it through the same pointer/camera/brush handlers as mouse left-button input. Preserve desktop mouse ID 0 rules, but never require touch IDs to be 0. Touches starting over UI cannot acquire the scene by moving off UI; other fingers or simulated mouse input cannot replace a captured gesture. Releasing over UI or cancellation always clears ownership and commits the current brush transaction; cancellation never invokes click selection/placement. Begin/End/Undo reset pointer state, and real touch-mode/layer/tool changes finish that gesture before applying the new selection. Validate Play movement+attack with two fingers, crossing/releasing independently, blocked events, hide/reopen and background/resume; validate Mod pan/paint, release over UI, canceled strokes and mode/tool switching on Android in addition to deterministic source regressions.

Character material animations use the shared `TextureAnimation` sampler but start at local time 0 on action/facing changes or forced replay, not the map's global phase. GIF/WebP tex entries play one internal cycle then hold the final frame for `CharacterAnimForm.animTimeInterval`; GIF ticks advance with bounded `TimeManager.GetDeltaTime`, while static-only clips retain their ordinary interval timers. Special returns to Idle only after the entire clip's internal cycles and final interval, and Die holds its final tex/frame. Track facing per body part so updating UpperPart cannot suppress LowerPart's rebind. Reuse a property block, preserve visibility/masks, and cancel/reject old instance-bound callbacks when changing animation or pool ownership.

`CharacterPlayAnim` is visual-only: a scene Character may exist before its first Show, so never index `animControllerDic` merely because `GetCharacterUnit` returned Data. Require the original registered Character Data, an active Instance bound to that Unit, and a live Product; absent/hidden/removed/recycled references no-op without showing or resurrecting anything. Visible Characters lazily register a missing controller through the normal `RegisterAnim` path; LoadModel and CheckAnim share this lookup. Controller Reset cancels old timers before clearing state (including Special/Die), Unregister cancels and removes just that Data's controller, and scene Reset cancels every timer before clearing the dictionary. Validate these paths in the isolated texture regression.

Story and scene transitions must coordinate:

1. End the active Mod or Play controller lifecycle.
2. Unload Map/Unit/event state.
3. Reset process-global Forms.
4. Load the next story tables in dependency order.
5. Load or copy logical map data from Core/Save/Cache.
6. Begin Map and the target mode.

`ModStory` Test/Play must show `UiLoading` and allow it to render for one frame before synchronous story save/unload work begins. Keep a transition-owned loading item active until `PlayManager`/scene loading has registered its own loading items, so the loading UI cannot flicker closed between phases.

ModStory's Scene unit Edit/Enter button captures the current Story/Scene IDs and uses an operation-owned LoadingManager.RunAsync loading item before saving. Allow loading to render through frame-end plus the next Update before synchronous SaveCoreStory/prefab/WangTile work. Reject duplicate clicks until completion, await the Task-returning StartLoadSceneUgc through ModManager.BeginScene, then close ModStory. Keep loading visible for this entire sequence; observe exceptions, release the item/entry guard in finally, and retain ModStory on save/load failure. The shared scene loading item also releases in finally, only after MapManager.Begin, appearance setup and the map-complete callback. The existing save pass persists Scene rows and generates only missing numeric Core map files, so a newly added Scene can be entered without a separate manual Save. ModAssetCtrl.CreateScene still registers only a Scene row; do not initialize or write a map during New. Run-ModStorySceneEntryRegression.ps1 executes the actual callback and LoadingManager against frame/save/load/UI spies for render-before-save, captured IDs, duplicate clicks, delayed success/failure, nested loading ownership and unchanged New behavior without touching real story files.

`Mod.btn_import` and `ModStory.btn_outPut` import/export `.png` story packages. Import reuses `AssetFilePicker.GetImage` with the translated title and `image/png` MIME/filter. Windows Editor/Standalone share the native Unicode image Open dialog; export retains the Unicode Save As dialog with `.png` default extension and native overwrite confirmation. Android import uses the existing NativeGallery image picker, and export uses `NativeGallery.SaveImageToGallery(byte[], Application.productName, fileName, callback)` to save the unchanged package PNG to the album. The custom ModPackageFileBridge, ModPackagePicker Java plugin and its Activity registration were removed; do not reintroduce a separate document/file-manager picker for Mod packages. NativeGallery returns an original path or a byte-for-byte cache copy; immediately read it with File.ReadAllBytes, never LoadImageAtPath/resize/re-encode. Handle the gallery's returned permission/busy state explicitly because rejected requests may not invoke a callback. New packages put compressed story data in actual lossless RGB pixels with a small cover preview; do not rescale, quantize, screenshot, or convert them to JPEG. Bind once in OnCreate, keep the UI's own importing/exporting guard (NativeGallery's Android busy query is not a reliable lock), and ignore import callbacks after the Mod panel hides/reopens. Cancellation is a no-op; errors show the appropriate Popup. Import registers a fresh local overview and refreshes the list without loading a story or clearing global Forms. Keep generated Mod UiBase/prefab bindings untouched.

Mod package import/export run through `LoadingManager.RunAsync`: show an operation-owned, unique loading item and wait until frame-end plus next Update before opening the picker or doing work; remove it in `finally` on success, cancellation or failure. `AssetFilePicker.GetModPackageAsync/ExportModPackageAsync` adapt the existing Windows dialogs/NativeGallery callbacks without changing selected paths or PNG bytes. UI guards remain active through completion. Hide cancels that operation and increments its version; stale callbacks cannot register an import, refresh a reopened panel, show an old notification, or release another operation's loading item. Decode/check/extract and export filesystem/PNG compression run on workers; Form registration, cover snapshot, UI and platform APIs remain on Unity's thread. Windows native dialogs and NativeGallery's final Android save can still briefly block; never put Unity/JNI calls into Task.Run merely to hide that limitation.

After the map-complete callback applies the initial/saved position, `PlayManager.BeginScene` finishes controller/player setup and immediately dispatches the pending Enter/FirstEnter event. Keep its `playSceneStart` loading item until the first normal event `LateUpdate` completes, so an immediate `ShowDialog` appears before the Play HUD can render. Do not run the interpreter an extra time during initialization or re-enable gameplay while the map is loading. Release the presentation loading item on scene/story exit and initialization failure too.

Play scene switches use `Main2StoryManager.ChangeSceneAsync` with a reentry guard: disable Play updates immediately, then use an operation-owned `LoadingManager.RunAsync` item to render Loading through frame-end plus next Update before saving/unloading the old scene. `UnloadScenePlay` owns the single old-map save, before controller reset; `PlaySceneController.End` must not save again. Await `LoadScenePlayAsync` through `BeginScene` and retain the existing first-event presentation item. The shared scene loading item starts before prefab/cache setup and is released in finally. Initial Play scene entry also waits for Loading to render. `PlayManager.UpdateScene` returns after dispatching the asynchronous switch, without updating old controllers again. `Run-SceneTransitionRegression.ps1` executes the production transition/unload methods and LoadingManager against frame/save/map/UI spies for render-before-save, reentry, async completion, failure cleanup and single-save ownership.

`LoadingManager` progress counts completed work, not caller-authored percentage milestones. `AddLoadItem(item, totalWork)` declares units before execution; the default zero-unit item is a visibility guard and contributes no denominator. `AddWork` reserves newly discovered units, `Advance` reports completed units (worker-safe), and `RunStep`/`RunStepAsync` pair the current stage with one successful unit. Duplicate Add is idempotent. Completed/removed children stay in the session counters until the last active item closes; cancellation/failure never fabricates completion, and a new session resets counts. Scene plans count prefab preparation, WangTile cache preparation, map reading/initialization/callback and each Object appearance product. Play initialization builds its actual new/saved/test action list and reserves the known scene/presentation stages before the first render; later scene entry only adds the discovered Object count. It keeps its item through the awaitable scene entry; `playSceneStart` counts the four controller begins, entry dispatch and first normal event LateUpdate. Initialization failure releases the reserved items too. Mod test, scene editing, import and export report their own real stages. Units describe completed stages/records, not elapsed-time weights.

The detailed `RunStepAsync` overload passes `Action<string,long,long>` (substage name, completed count, total count). Declare all known substages with `0/0` first, then replace those totals with actual file/byte/PNG-row counts when discovered. Substage fractions are averaged within the single reserved outer unit; byte, row and file units never share a denominator. Reporter callbacks expire on phase completion/change and cannot mutate another session with the same item name. `RunStepsAsync` materializes resource actions, renders first, and renders again after an 8 ms batch budget; a single resource remains synchronous. Prefab rebuilding and WangTile generation use these batches while preserving the existing synchronous helpers, variant registration order and Story cache reuse. Loading also yields after map initialization. Large source assets are Base64-streamed in complete 3-byte blocks during packaging, reporting actual input bytes; PNG encoding/decoding report rows and decompression reports bytes. Import reports validation/extraction file counts and registration, then tracks the Story-list refresh as a separate stage. Waiting for the picker does not complete work. A native file dialog, synchronous Story save, list refresh or one large texture can still block a frame.

`UiLoadingCtrl` renders counted progress as a percentage, shows `…` for unknown/guard-only work, retains the highest displayed value within one session when more work is discovered, and caps the still-active display at 99 until loading closes. Repeated Show within a session does not reset its text.

`LoadingManager.currentPhase` selects the most recently reported unfinished active stage; reserving future work or declaring `0/0` substages must not replace its title. `SetPhase` accepts an optional display title key. Real worker substage reports update the current key under the progress lock; localization and UI writes remain on Unity's thread. `UiLoadingCtrl` writes the localized source key through `txt_title.oriText`, using `CommonText_TextBase.xlsx` / generated `CommonTextForm` for English/Chinese descriptions. It refreshes the title independently of percentage changes and refreshes on language changes. Unknown/visibility-only stages fall back to the `loading` key. Do not edit generated `UiLoadingBase` or expose internal object IDs, class names or counters in the title.

Loading has no per-stage diagnostic logging, UI heartbeat logging, diagnostic timers or file I/O. `Run-LoadingProgressRegression.ps1` exercises the actual manager, UI text controller and Play Story-entry branches with frame/UI/data spies; retain the scene-entry, transition and package-lifetime fixtures too.

Android gallery providers may return `pickedMedia.tmp` when MIME metadata is absent. Never reject a Mod image only for its cached filename extension: `GameSaveController.ImportPackage` verifies PNG signature and package content. The Windows native picker still checks `.png`. Never delete a gallery-returned path, which can refer to the user's original image.

Test consecutive stories and repeated mode entry; many failures are stale singleton, listener, Form, or cache state rather than local logic.

Dialog MainText audio and DialogBg video use pooled AVPro MediaPlayers. On every Show (including active-panel clip changes) and Hide, Pause to clear AVPro's hidden-player resume flag, then CloseMedia before loading the new clip; an absent/missing audio or video leaves the player closed. DialogBg owns the completion listener returned by VideoAssetForm.Data.Play and removes only that listener before closing/rebinding, including failed opens, so an interrupted video's callback cannot advance a later dialog. Do not clear unrelated player listeners or modify generated UI/prefabs for this cleanup.

Play camera following is gated centrally by `CameraInstance.followsPlayer`; `PlaySceneController.SetCamera` routes both ordinary per-frame following and current-character replacement through `FollowPlayer`. Scripted `MoveCamera`/`MoveCameraTo` own the root while this bool is false, including after arrival. `RestoreCamera` restores the bool and immediately follows the current registered main Character, leaving the root still if no Character exists. Reset manual ownership on camera Register/disable and Play scene End, and invalidate older motion tasks with a per-camera version rather than adding an independent runner. A motion task consumes bounded delta only once per `Time.frameCount`, since `StartTask` and the scheduler may both poll in its first frame; control/scene invalidation must still complete before this guard. Keep progress position updates active while camera following is suspended and keep SceneShake on the camera child only.

Stick capture accepts its own `rtf_area.gameObject` or moving center knob's GameObject, never an arbitrary UI object. The center knob and area in `go_stick.prefab` are siblings, not ancestor/child. The knob's Graphic is a raycast target and wins center hits; Q/E instances intentionally disable the area's Graphic, so do not globally disable knob raycasts or require only area hits. A zero-displacement center Down still captures the pointer, allowing subsequent drag to leave the movement deadzone. Keep the authored hierarchy, raycast settings and generated bindings unchanged.

The updated Stick Model binds `go_stick` (the whole root), `go_area`, `rtf_area` and the nested `img_` under the center's Mask; `img_stick` and the generated `rtf_stick` field are gone. `UiStickCtrl.StickRect` walks from the bound icon to the direct child of the root once and caches that moving center RectTransform in its runtime Model, preserving the existing movement/normalization and sibling raycast behavior without moving the input root or editing generated UiBase. Only Play's LightAttack, E and Q render equipped `SkillProductForm.icon` images in `img_`; the movement stick does not receive a skill icon. Resolve the current Character's exact equipped Skill Product and texture, and blank the icon for absent/nonpositive IDs or missing records. `SetIcon` updates just the image and its Param/Model icon so later child OnShow/reopen keeps it; clear stale overrides/texture bindings and hide only the empty icon, never the raycastable center knob. Parent Refresh updates all three icons; PlayerTouchOpt OnShow also rebinds LightAttack after creating its fresh Params. Image refresh must not call OnShow/SetShow on an already valid captured stick or reset its pointer/aim. Mobile input regression covers inherited prefab Graphic flags, saved icon bindings, nested geometry and character/equipment/reopen/missing-image transitions on both platform branches.

Play's move/LightAttack sticks use fixed mode (`UiStickParam.floating = false`), like Q/E. Keep both knobs visible while idle and preserve the authored area center, Graphic settings, geometry and generated bindings. Center Down captures a neutral gesture; an off-center Down already has direction relative to that fixed center, and later drags never redefine the origin. Fixed mode retains its area-width normalization, half-width visual clamp and Play direction deadzone. Release, cancellation and blocking clear ownership/direction; the ordinary UI update recenters the still-visible knob. Hide/reopen clears the gesture and restores the authored center. Both sticks may capture independent fingers simultaneously. The generic optional floating mode remains available to other callers, including its press-relative origin, temporarily transparent enabled area Graphic, hidden idle knob and restoration before reconfiguration. `Run-MobileInputRegression.ps1` covers Play fixed centers/visibility/lifecycle, independent fingers and generic floating-mode behavior; actual Android raycasts still require smoke testing.

Play Q/E share `UiPlaySceneMainCtrl`'s skill callbacks but must pass their own SkillType to scene selection. Convert screen XY stick direction to world XZ; a center/deadzone click retains the previous facing instead of invoking LookRotation with zero. Start checks use CanUseSkill only when capturing; continuation permits null/current-own skill, but rejects disabled skills, blocked/missing progress and another selected skill. Refresh retains a still-valid captured skill stick instead of hiding it merely because CanUseSkill's start-only no-current-skill check is false during aiming. Ordinary release validates continuation, clears only its own selection before UseSkill's synchronous CharacterSkillEvent/UI refresh, and then uses its equipped skill. Canceled/blocked/hidden gestures only clean up and never cast or clear another skill's selection. Include both center-click and center-to-edge drag in the mobile regression, in addition to direct area hits; source/spies do not replace real UGUI raycast and device checks.

Under `UNITY_ANDROID`, PlayerTouchOpt's nonzero move direction also calls the existing `SetPlayerRotation` when no attack pointer is captured, no Skill is selected, and at least `0.1` real seconds have elapsed since attack-stick activity. Store transient `lastAttackStickTime` in its Model using `Time.unscaledTime`; held callbacks (including neutral holds), ordinary release and cancellation/Hide refresh it. The pointer-capture check protects the frame before the attack callback runs. Show resets the timestamp to negative infinity so an unused/reopened attack stick does not delay initial movement facing. Idle/zero motion must not invoke LookRotation; Q/E aiming and desktop mouse/keyboard facing keep priority/behavior. Do not change movement delta, map collision/navigation or save data for this input-only rule. `Run-MobileInputRegression.ps1` checks before/at/after the `0.1`-second boundary, long holds, neutral reinteraction, cancellation, skill priority, UI reuse and desktop exclusion.

## UiHolder generation model

Core files:

- `Assets/Z_Level3/Z_UI/Core/UiManager.cs`.
- `Assets/Z_Level3/Z_UI/Core/UiPreloadConfig.cs`.
- Inspector-assigned `UiPreloadConfig` ScriptableObject assets.
- `Assets/Z_Level3/Z_UI/Core/Basic/Frame/UiHolder.cs`.
- `Assets/Z_Level3/Z_UI/Core/Basic/Frame/UiCtrl.cs`.
- `Assets/Z_Level3/Z_UI/Core/Editor/UiHolderEditor.cs`.
- Product output: `Assets/GameSample/UiBase`.

Flow:

```text
Prefab + UiHolder hierarchy
→ UiHolderEditor parses names
→ Ui{Name}Base.cs partial View/Ctrl/Model/Param
→ hand-written partial Controller under GameSample/MyScripts
→ UiManager.ShowUi<T>() / CloseUi<T>()
```

Top-level generated Panels use a persistent Prefab or Prefab Variant as their
visual source. `UiManager` and each generated top-level `UiHolder` select a
`UiPreloadConfig` asset in the Inspector. The Manager reads its selected registry;
a successful Generate upserts the saved prefab source by `uiName` into the
Holder's selected registry. Keep those references aligned for each scene/product.
Pure scene holders must be prefabized first; apply relevant instance changes or
Generate in Prefab Mode so code and runtime bindings use the same source.

Lifecycle details that matter in this project:

- `UiManager.ShowUi<T>()` normally reuses the first controller instance.
- `UiHolder` guards `OnCreate()` with the controller's `inited` state, but runs
  `OnShow()` every time the UI is shown.
- `UiContainer` pools and reuses child controllers.
- `UiContainer.AddReal` restores sibling order before activation, so pooled rows retain the current render order after filtering or count changes rather than their former hierarchy order.
- Story switches do not guarantee that Mod UI objects or their Model state are
  destroyed. Reset story-scoped filters and selections explicitly when required.

Supported hierarchy prefixes include `btn_`, `txt_`, `ipt_`, `go_`, `img_`, `rimg_`, `as_`, `scr_`, `sld_`, `sta_`, `rtf_`, and `dp_`.

Shared Lab-list contract:

- Form-backed UI rows and selection entries use ascending Data primary keys (`id`, or `uid` for those Forms), never dictionary/insertion or display-name order. This includes ModStoryMapObjectList's Texture/Mask/Object rows, product/scene/parameter/asset lists, Play Form rows and Form selection windows. Build filtered rows in that order, retain special All/Unclassified/None rows in their existing slots, and append the New/Add row last. Do not reorder authored event execution lists, animation frames, or enum-defined equipment/skill slots.
- Concrete Lab rows use ascending `LabForm.id`; identical path aliases remain deduplicated to their lowest ID. Event Program category rows use the lowest Lab ID for that first-level name; command/program choosers order categories by Lab ID and the merged category's actual entries by Data UID, including legacy aliases. Sorting is UI-only; do not reorder Form registries or saved authoring sequences.
- `scr_labs.sta_state` uses `0 = All`, `1 = Unclassified (labId=0)`, `2 = concrete Lab`, and `3 = New`; `sta_` remains the independent selection state.
- ModStoryEvent Program renders one `scr_lab` list backed by first-level `EventProgramDataForm` Labs (`lv1Lab`); the second list is removed. `labId=0` is unclassified, and label changes assign a flat Lab.
- New Event labels create a first-level `LabForm` path with `belong = nameof(EventProgramDataForm)` and remain listed even before a Program uses them. Its `ipt_lab` and `btn_deleteLab` rename or delete the selected first-level label, moving all matching Program references first; the Form schema does not change.
- Build Lab rows from `LabForm.DatasByBelong[nameof(ConcreteForm)]`, so empty labels remain visible and Lab identity keeps its concrete `belong`.
- In UI filters, `null` means All; `LabForm.NoneId == 0` remains unclassified and is not interchangeable with `null`.
- Render the unclassified row only when the current screen has actual `labId=0` data; when it disappears, reset an active unclassified filter to the screen's valid fallback instead of leaving an invisible selection.
- `UiPlayDataBackpack` is a read-only Label filter: show All, optional Unclassified, and existing Item labels, but never render the New row or create labels from Play mode.
- `UiPlayDataCharacter` resets to its Data module each time the panel is shown; Equip and Skill remain user-selected secondary tabs for that opening.
- `UiPlayDataCharacterSkill` lists only equipped Skills that resolve to a `SkillProductForm` record. Each slot's `txt_` shows the translated `SkillType`; selecting one shows that type in the page's `txt_`, the Skill name in `txt_name`, and `SkillProductForm.desc` in `txt_desc`. There is no `txt_type` binding. `UiModStorySkillUnitOverview.ipt_introduction` edits that same persisted description field.
- Play scenes may have `ProgressForm.characterUid == 0` after the Mod story config removes the main character. `PlaySceneController` then keeps a null player and positions the camera from saved progress; the main HUD tolerates the pre-player `OnShow`, refreshes after player setup, omits character parameters/actions and missing team rows, and guards player-only collision/interact callbacks. Mod story config displays an empty main-character name until one is selected; when adding a team or active-team character while the current UID is `0`, it assigns the added character as main and keeps that main character active. Core editing does not directly rewrite `Save/pf`; `LoadSaveStory` repairs invalid saved current-character IDs separately.
- For New, prompt through `NotifyManager`, resolve with `LabForm.GetOrCreateDisplayName(input, nameof(ConcreteForm))`, then select a nonzero result and refresh.
- Mod list screens with `ipt_lab` and `btn_deleteLab` expose those controls only for a concrete selected Lab. Renaming reuses a matching Lab and moves every reference in that concrete Form; deletion moves references to unclassified before removing the Lab. Map Texture, Mask, and Object lists apply this within the currently selected map type.
- After renaming a prefixed object in a shared prefab, regenerate every owning Panel and update all partial Controller references to the generated field.

Rules:

- Do not hand-edit `UiBase`; the generator deletes and rewrites its target file.
- Do not restore a scene or `UiManager` preload list, and do not hand-write object references in the config asset.
- `UiHolderEditor.Generate` first persists the current prefab modifications of the prefab that owns this `UiHolder` (the source Generate reads): it saves the dirty Prefab Mode contents when the open prefab is that same prefab asset, and otherwise applies that owning prefab's instance overrides (scene instance, or a nested instance inside another prefab stage). Never save the enclosing prefab just because the holder sits inside it; a failed save/apply aborts Generate instead of emitting stale bindings. Pure scene holders have nothing to save.
- Do not add an implicit Resources/default-config fallback; missing Manager or Holder references are configuration errors.
- Keep the registry free of null entries and duplicate `uiName` values; only top-level Panels are registered.
- Put state in the partial Model, input in Param, rendering references in generated View, and behavior in the partial Controller.
- The four `ModStoryParameter` default-parameter lists use `btn_value/txt_value` on Arg rows, sharing `ModAssetCtrl.ChooseBasicCmd` with per-Product parameter editing. Numeric and Text inputs replace the Box's scalar type and clear stale dictionary/reference fields; Text pre-fills its actual string and both types invoke completion after a valid input. Synchronize the default row's saved `v` immediately after selection, before a generated `Copy()` can create a Product from an old serialized default; do not overwrite existing Product overrides. Pending callbacks capture the original Data/Box and validate the registered Data identity before publishing/refreshing; template rows with no Param stay inactive.
- `ModStoryEvent.btn_globalVar` selects `ModStoryGlobalVar` (page `1`), mutually exclusive with Custom Events (page `0`), and updates both selection states. Its global-variable Arg list renders `EventGlobalVariableForm` rows in ascending UID with New last, provides unique nonempty names and numeric/Text initial-value editing, and uses `ModAssetCtrl.CreateGlobalVar/RenameGlobalVar/DeleteGlobalVar`. Value editing uses a draft Box and commits only while the original record remains registered, so cancelling, deleting a row or switching Stories cannot revive/retarget old work. The panel edits Core defaults; normal Story save writes `egvf`, new Play/Test loads them, and resumed Play retains its own Save values without reinitializing them from Core.
- Bind callbacks and create scroll containers once in `OnCreate()`.
- Apply incoming Param and call `Refresh()` in `OnShow()`.
- Character, Item, Object and MapTexture Config render their shared scene triggers through `Ui.EventChoose.UiSceneEventChooseList.Render`, using the generated `go_eventChoose` Model as a pooled `UiContainer` template. The fixed order is CharacterTouch, CharacterLeave, ObjectTouch, ObjectLeave, TileTouch, Show, PerSecond, BoundaryTouch, Interact, ClickMinimap, LeaveScene, Destroy (full saved keys keep the `on...Event` spelling). `onDestroyEvent` uses the bilingual ModText label from its source workbook and the same prototype/local event window, with no new prefab/generated UI fields. Hide ClickMinimap when minimap is disabled without removing its saved trigger; Item's Use/Equip/Disequip remain separate.
